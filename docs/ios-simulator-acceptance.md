# Симулятор для приёмки iOS +72

Workflow `ios-simulator-acceptance` готовит Debug `.app` для iOS Simulator из тех же файлов `lib/`, `assets/`, `ios/`, `pubspec.yaml` и lockfile, что IPA +72 (source `f47895509bcf1da287accb68f45b27acdff63d25`). CI checkout может содержать новые скрипты; различия исходников приложения относительно source отклоняются. Версия остаётся `1.0.0+72`, Flutter `3.47.1`, Xcode `26.6`.

Запуск ручной, без inputs, signing/API secret groups, store upload и запуска набора app tests. Production API/меню/version URL те же, что у IPA. Симулятор использует рабочий API: для сценариев с заказами сначала определить тестовые учётные записи и принадлежность тестовых данных по AGENTS.md.

Артефакты: `build/ios/iphonesimulator/Runner.app` для Quick Launch, архив `build/release/ios-simulator/ios-simulator-1.0.0+72.zip` и `simulator-report.json`. CI проверяет идентификатор, версию, платформу Simulator, семейства iPhone/iPad и четыре ориентации iPad. Отчёт `prepared` означает готовность артефакта, а не успешную приёмку.

После сборки проверить доступность App Preview. На 06.10.2026 кабинет предлагает Start trial / 100 free minutes; trial ещё не включён. По [документации Codemagic](https://docs.codemagic.io/yaml-distributing/app-preview/) функция связана с командой и тарифом; после пробных минут возможна оплата. Не активировать тариф или платные минуты без конкретного разрешения владельца. Не передавать `.app` другому облачному сервису без согласования.

В доступном App Preview запустить Quick Launch, проверить iPhone и iPad: запуск, меню/фото, навигацию, разрешённый тестовый вход, историю/черновики, повторное открытие; на iPad — ориентации и доступность элементов при изменении размера. Записать модель симулятора, iOS, результаты и скриншоты. Для сохранения данных сравнивать состояние в одной сессии: облачный сервис может сбрасывать хранилище между сессиями.

Это отдельная Debug-сборка для симулятора. Она не доказывает установку магазинного IPA через TestFlight, работу Release на физическом устройстве или сохранение данных при обновлении установленной версии. Итог фиксировать как «приёмка на симуляторе»; физическая приёмка остаётся отдельной по [рекомендации Apple](https://developer.apple.com/documentation/xcode/testing-a-release-build).

## Запуск существующего артефакта в CI

По выбору владельца используется `ios-simulator-smoke`, без создания Team или App Preview. Он скачивает именно проверенный архив указанного выше CI через существующий `CODEMAGIC_ARTIFACT_API_TOKEN`, проверяет SHA256/Info.plist, сохраняет права файлов через `ditto` и не пересобирает приложение. Импортируется существующая группа `app_store_connect_release` из-за размещения в ней Codemagic token; Apple ключи не используются, Apple API не вызывается. Все эти секреты исключены из окружения запуска Simulator и приложения.

CI выбирает доступный iOS runtime и создаёт по одному временному iPhone/iPad (предпочтительно iPhone 16/iPad A16). Устанавливает +72, снимает первый экран, экран через 30 секунд и после повторного открытия. Сверяет стабильность PID при наблюдении, сохраняет редактированные stdout/stderr/командный журнал и report. Удаляет только собственные созданные симуляторы. Скриншоты и report публикуются как artifacts `build/release/ios-simulator-smoke/`.

Успех команды запуска/PID не доказывает готовность интерфейса. Report `captured/pending_visual_review` требует просмотра PNG; чёрный экран, launch screen, ошибка сети или предупреждение Flutter считаются нерешёнными. Проверка этих первых экранов не подтверждает навигацию, вход, историю, сохранение заполненного черновика, повороты iPad или физическую приёмку. Сценарии авторизации/заказов не запускаются: тестовые учётные записи для CI ещё не определены.

## Сценарий навигации, подготовлен 06.10.2026

Отдельный ручной workflow `ios-simulator-navigation` вызывает `check_ios_simulator.py --navigation`, использует тот же проверенный Simulator +72 без пересборки. Smoke остаётся доступным отдельно. Локальный Maestro CLI 2.11.0 закреплён по SHA256 официального ZIP; Java 17 должен присутствовать на машине Codemagic. Облачный Maestro не используется, аналитика и проверка обновлений отключены. Используется существующая группа `app_store_connect_release` только ради artifact token; Apple credentials в окружение драйвера не передаются.

Анонимные действия на iPhone и iPad: меню разделов, Меню, текущая/следующая недели, Доставка с проверкой «Условия доставки», возврат на главную. На iPad четыре ориентации с проверкой доступности недель и размеров PNG. Для каждого устройства сохраняются flow.yaml, JUnit, журналы и снимки в `build/release/ios-simulator-navigation`. Возможное отсутствие Java17/несовместимость драйвера/невидимая semantics-метка остановят сценарий с ошибкой; первый native запуск ещё не выполнен. Не ослаблять обязательные assertions до optional ради зелёного результата.

После успешного CI просмотреть снимки меню, фотографий и каждой ориентации. Статус assertions_passed_pending_visual_review означает только прохождение команд; фото, вёрстку и возможные Flutter errors оценивать отдельно. Сценарий не подтверждает вход, историю, черновики, изменение размера окна, сохранение данных при обновлении и физическую приёмку Release IPA. Подготовка локальная, commit/push/CI ещё не выполнены.
