# Симулятор для приёмки iOS +72

Workflow `ios-simulator-acceptance` готовит Debug `.app` для iOS Simulator из тех же файлов `lib/`, `assets/`, `ios/`, `pubspec.yaml` и lockfile, что IPA +72 (source `f47895509bcf1da287accb68f45b27acdff63d25`). CI checkout может содержать новые скрипты; различия исходников приложения относительно source отклоняются. Версия остаётся `1.0.0+72`, Flutter `3.47.1`, Xcode `26.6`.

Запуск ручной, без inputs, signing/API secret groups, store upload и запуска набора app tests. Production API/меню/version URL те же, что у IPA. Симулятор использует рабочий API: для сценариев с заказами сначала определить тестовые учётные записи и принадлежность тестовых данных по AGENTS.md.

Артефакты: `build/ios/iphonesimulator/Runner.app` для Quick Launch, архив `build/release/ios-simulator/ios-simulator-1.0.0+72.zip` и `simulator-report.json`. CI проверяет идентификатор, версию, платформу Simulator, семейства iPhone/iPad и четыре ориентации iPad. Отчёт `prepared` означает готовность артефакта, а не успешную приёмку.

После сборки проверить доступность App Preview. На 06.10.2026 кабинет предлагает Start trial / 100 free minutes; trial ещё не включён. По [документации Codemagic](https://docs.codemagic.io/yaml-distributing/app-preview/) функция связана с командой и тарифом; после пробных минут возможна оплата. Не активировать тариф или платные минуты без конкретного разрешения владельца. Не передавать `.app` другому облачному сервису без согласования.

В доступном App Preview запустить Quick Launch, проверить iPhone и iPad: запуск, меню/фото, навигацию, разрешённый тестовый вход, историю/черновики, повторное открытие; на iPad — ориентации и доступность элементов при изменении размера. Записать модель симулятора, iOS, результаты и скриншоты. Для сохранения данных сравнивать состояние в одной сессии: облачный сервис может сбрасывать хранилище между сессиями.

Это отдельная Debug-сборка для симулятора. Она не доказывает установку магазинного IPA через TestFlight, работу Release на физическом устройстве или сохранение данных при обновлении установленной версии. Итог фиксировать как «приёмка на симуляторе»; физическая приёмка остаётся отдельной по [рекомендации Apple](https://developer.apple.com/documentation/xcode/testing-a-release-build).
