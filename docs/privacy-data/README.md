Готовые Web/Android +4 используют API `https://hleb-sol.su/Zakaz_http/hs/Obmen/` и публичные файлы `https://obedmoscow.ru/data/`. [AppConfig](../../lib/core/config/app_config.dart) принимает только HTTPS; публичный транспорт не добавляет токен к файлам. Это подтверждает транспорт клиента, но не защищённость дальнейшей обработки на серверах и не независимую сертификацию безопасности.

Внешние телефонные/почтовые ссылки передают действие выбранному приложению пользователя. В проверенном клиенте не найдено чтение контактов, SMS, пользовательской фототеки или отправка писем без действия пользователя. Серверная отправка кодов на email входит в поток регистрации/смены почты; почтовый подрядчик неизвестен.

## SDK и платформенные сведения

Дополнение FL-06-20c (общие исходники, ещё не в готовой +4): [CartSubmissionStore](../../lib/features/cart/cart_submission_store.dart) сохраняет локально владельца, submissionId, неизменное тело заказа (включая даты/revision, блюда/количества/скидку) и предварительные суммы. Область включает API/окружение. Токен, deviceId и пароль в этот снимок не добавляются. Запись удаляется после подтверждённого завершения и сохранения черновика; при неизвестном исходе сохраняется для проверки. Это локальное хранение переданного заказа, не новый поток сбора SDK; механизм не является зашифрованной базой. Старые ключи без области API не мигрируют автоматически. См. [карточку](../tasks/FL-06-20c.md).

Прямые зависимости: Riverpod, go_router, http, flutter_secure_storage, shared_preferences, cached_network_image, url_launcher, package_info_plus, intl; точные разрешённые версии — в pubspec.lock. В lib/pubspec не найдены интеграции рекламных SDK, Firebase, Sentry, Crashlytics, геолокации, камеры или телеметрии. Поиск `print`, `debugPrint`, `developer.log` не обнаружил вызовов в lib. Это ограниченный аудит исходников, а не доказательство отсутствия серверных журналов или всех возможных действий транзитивного SDK.

Статическая проверка `aapt dump permissions` сохранённого APK +4: `android.permission.INTERNET` и собственное `ru.obedmoscow.polevayakuhnya.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`. Разрешений камеры, местоположения, контактов, SMS и Advertising ID в этом выводе нет.

Прочитаны локальные iOS privacy manifests: flutter_secure_storage_darwin 0.4.3, package_info_plus 10.2.1, shared_preferences_foundation 2.5.7, sqflite_darwin 2.4.4, url_launcher_ios 6.4.2. В них tracking=false и пустые collectedDataTypes; shared_preferences_foundation объявляет UserDefaults с reason `1C8F.1`. Собственный PrivacyInfo.xcprivacy в ios не найден. Эти manifests описывают библиотеки и не отменяют декларацию данных, которые приложение отправляет в 1С. Состав итогового iOS-архива и его приёмка не проверены.

## Google Play — черновик Data Safety

Основание: [официальное руководство](https://support.google.com/googleplay/android-developer/answer/10787469?hl=en). Передача с устройства — сбор; локальное хранение отдельно. Ephemeral также учитывается в анкете. Обработчик по поручению может подпадать под исключение sharing, но без сведений о подрядчиках такой ответ не подтверждён.

| Пункт | Рабочий ответ / действие до отправки |
|---|---|
| Собирает ли приложение данные | **Да**: регистрация, авторизация, заказы |
| Personal info → Name, Email address, User IDs | Включить имя, email, идентификатор аккаунта/логин; назначение App functionality и Account management |
| Device or other IDs | Включить persistent UUID `deviceId`, используемый для авторизации/привязки; назначение App functionality / Account management. Security purpose отмечать только после сверки с фактическим использованием сервером |
| Financial info → Purchase history | Включить отправляемые заказы блюд; App functionality. Банковские реквизиты или платёжные карты из этих запросов не следуют |
| Пароль, токен, коды подтверждения | Не исключать из инвентаризации; при заполнении сверить применимые категории credentials/User IDs/Other personal info в актуальной форме. Не объявлять ephemeral без серверных сведений |
| Phone number, Address, Location, App activity, Diagnostics | Не включать автоматически из-за профиля или HTTP. Уточнить серверное логирование, дополнительные потоки и использование IP; добавить только соответствующие фактическим данным категории |
| Обязательность | Гостевое меню работает без входа. Предварительно сбор аккаунтных данных — optional относительно гостевого использования; поля обязательны для выбранных регистрации/заказа. Проверить определение required/optional в форме для каждого типа и всех путей его получения |
| Передача третьим лицам | **Не определено**: нужен перечень получателей, роли, цели, соглашения и серверные потоки; нельзя подтвердить No |
| Encryption in transit | Клиентские HTTPS-пути подтверждены; окончательный ответ о всех собираемых данных требует проверки остальных потоков/SDK и серверной передачи |
| Ephemeral processing | **Не подтверждено**; не выбирать Yes только потому, что клиент хранит контекст в памяти |
| Удаление аккаунта / URL | FR-A6 открыт, рабочий путь и URL не приняты; нельзя подтвердить наличие |
| Независимая проверка безопасности | Не подтверждена, не заявлять прохождение |

Виды данных могут иметь несколько целей; не добавлять рекламу/маркетинг/аналитику без подтверждённого использования. Перед отправкой сверить все ответы с конкретной выпускаемой сборкой и сервером.

## Apple — черновик App Privacy

Основание: [App Privacy Details](https://developer.apple.com/app-store/app-privacy-details/). Apple связывает collection с доступностью данных дольше обработки запроса в реальном времени. Linked to user определяется связью с аккаунтом; случайный UUID сам по себе не означает tracking. Не использовать исключение optional disclosure для обычных регистрации и заказов.

| Категория | Предварительная декларация |
|---|---|
| Contact Info → Name, Email Address | App Functionality, linked to user; передача подтверждена, серверное хранение подтвердить до анкеты |
| Identifiers → User ID, Device ID | App Functionality, linked to user: логин/идентификатор аккаунта и UUID устройства участвуют в авторизации |
| Purchases → Purchase History | App Functionality, linked to user: заказы и история; серверное хранение подтвердить |
| Credentials, IP/журналы, телефон/адрес профиля | Нужна сверка удержания, назначения и применимых категорий в актуальной форме; не скрывать сведения только из-за отсутствия отдельного текстового поля |
| Data Used to Track You | В проверенных клиентских интеграциях tracking не найден. Финальный ответ зависит также от обработки разработчиком/подрядчиками, которая пока не определена |

Нельзя выбрать «Data Not Collected» на основании пустых SDK manifests. Проверка manifests итогового iOS-архива остаётся частью отложенной подготовки iOS.

## RuStore — сведения для подготовки кабинета

По [требованиям RuStore](https://www.rustore.ru/help/developers/publishing-and-verifying-apps/requirement-apps) нужно согласовать обработку пользовательских данных и применимые разрешения. Кабинет не открывался; поля Google/Apple не выдаются за структуру формы RuStore.

Черновик описания обработки: «Приложение передаёт в сервер 1С данные для входа, регистрации и подтверждения почты, идентификатор установки и состав заказов. Профиль и история отображаются из 1С. Токен и черновик корзины сохраняются локально; меню и фотографии загружаются с сайта. Подрядчики, сроки хранения и порядок удаления подлежат согласованию». Последнее предложение — внутренняя отметка подготовки, не текст для публикации вместо политики.

Разрешения Android — из APK выше. Согласие, оператор, цели, получатели и рабочая политика должны соответствовать реальной обработке; заполнение кабинета не выполнено.

## Условия до отправки

1. Владелец определяет оператора, контакты для обращений, серверы/почту/доставку/аналитику и получателей данных; для каждого — набор данных, цель, роль и условия обработки.
2. Устанавливает сроки и основания хранения аккаунта, заказов, кодов, токенов, журналов и резервных копий; исключения после удаления описываются отдельно. «Не определено» не заменять произвольным сроком.
3. Согласуется и публикуется доступная политика с постоянным URL. В [материалах магазинов](../store-listings/README.md) privacy.url пока null; рабочий #terms содержит неподходящий текст о продаже ПО и не принят как политика приложения.
4. Закрывается FR-A6: отключение устройства и logout не удаляют аккаунт. Для приложения с созданием аккаунта Google требует путь запроса внутри приложения и веб-ресурс ([правило](https://support.google.com/googleplay/android-developer/answer/13327111?hl=en)); Apple требует инициирование удаления из приложения ([правило](https://developer.apple.com/support/offering-account-deletion-in-your-app/)). Наличие context_v1 нельзя считать исключением без отдельного обоснования.
5. После согласования проверяются декларации по выпускаемой версии; Google Play/RuStore — в кабинетах, Apple — после снятия запрета на iOS и подготовки архива. Подача и приёмка отдельно от этого аудита.
