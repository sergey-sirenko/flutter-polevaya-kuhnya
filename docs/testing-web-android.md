# Проверки Web и Android

Решение пользователя от 28.09.2026: живую проверку Web выполняет пользователь на `https://flutter-test.obedmoscow.ru`. Для этого тестовая сборка выкладывается по SSH. Запуск на `localhost` не является приёмкой Web: этот адрес не входит в разрешённые origin API.

## Что делает LLM

Постоянное правило пользователя от 28.09.2026: после каждой подзадачи или принятого решения всегда предлагать **пересобрать Web и обновить тестовый `flutter-test.obedmoscow.ru` по SSH** как самый быстрый способ проверки пользователем. Принятые решения должны согласованно отражаться в мобильных приложениях и Web; перед сборкой сверять код и параметры окружения. Канонические правила — [AGENTS.md](../AGENTS.md), разделы «Источники и архитектура» и «Проверки и выпуск». Для документационных правок указывать, нужна ли пересборка; если сборка уже выложена, предлагать проверку опубликованной версии. Предложение само по себе не является поручением на выкладку.

Локально, без выкладки на сервер и без ввода реквизитов:

- `flutter analyze` и `flutter test`;
- сборка тестового Web-артефакта командой ниже;
- просмотр экранов с синтетическими адресами `.invalid`, если нужно проверить вёрстку без API;
- пробы хранилища из разделов ниже. Они не ходят в 1С.

LLM не объявляет вход, меню и заказы проверенными в браузере, пока пользователь не открыл выложенную сборку.

Тестовая сборка для flutter-test, из корня проекта:

```powershell
flutter build web --release --no-pub --dart-define=APP_ENV=test --dart-define=API_BASE_URL=https://hleb-sol.su/Zakaz_http/hs/Obmen/ --dart-define=DATA_BASE_URL=https://obedmoscow.ru/data/ --dart-define=APP_VERSION_URL=https://flutter-test.obedmoscow.ru/version.json
```

Результат: `build/web/`. Команда ничего не копирует на сервер. Это не выпуск на `new.obedmoscow.ru`: для него отдельная prod-команда в [release-builds.md](release-builds.md).

Ту же команду выполняет [tools/build_web_test.ps1](../tools/build_web_test.ps1). По FL-07-07b тестовый Web читает меню и фотографии напрямую с рабочего сайта, как Android. Публичные файлы не получают токен 1С; CORS файлов и CORS API проверяются отдельно. Маршрут `/data/` тестового домена может оставаться 503: новая сборка к нему не обращается.

## Быстрая сборка, выкладка и откат тестового Web

Из корня Flutter-проекта откройте PowerShell 7 и выполните:

```powershell
pwsh -NoProfile -File .\tools\deploy_web_test.ps1
```

Скрипт собирает release Web для `APP_ENV=test`, API 1С и данных `https://obedmoscow.ru/data/`, затем публикует результат на `https://flutter-test.obedmoscow.ru`. Для выкладки уже собранного `build/web` укажите `-SkipBuild`. SSH host по умолчанию — `185.233.200.63`; если у вас есть алиас SSH, его можно передать `-SshHost my-server`. Пароли и ключи скрипт не принимает: используется SSH-конфигурация пользователя с `BatchMode`.

Скрипт сверяет новую версию с активной и отказывается ставить такую же или более старую. Архив и манифест с SHA-256 остаются локально в `build/deploy-web-test/<UTC-время>/`. Перед переключением предыдущий сайт архивируется и сохраняется каталогом на сервере в `/var/backups/flutter/WEBTEST-<UTC-время>/`. Staging и активные файлы сверяются по имени, размеру и SHA-256. Подмена каталога происходит на одном файловом разделе; если это условие не выполняется, выкладка прерывается до переключения. Caddyfile не меняется и reload не нужен.

После успешного запуска скрипт печатает путь резерва. При проблеме верните именно эту предыдущую версию:

```powershell
ssh 185.233.200.63 "sh /var/backups/flutter/WEBTEST-<UTC-время>/rollback.sh"
```

`<UTC-время>` замените точным именем каталога из вывода выкладки. Откат проверяет публичный `version.json`; новую версию сохраняет внутри того же каталога резерва как `web-after-rollback`.

После выкладки откройте `https://flutter-test.obedmoscow.ru/menu`. Если страница была открыта до обновления, нажмите Ctrl+Shift+R. Проверьте, что отображаются блюда и фотографии, затем сообщите о результате. Публичная версия сборки доступна по `/version.json`.

Задача и реализация скрипта: [FL-06-14a](tasks/FL-06-14a.md). Для короткого отдельного шага сборки без публикации доступен [build_web_test.ps1](../tools/build_web_test.ps1).
