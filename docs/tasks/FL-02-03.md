# FL-02-03 — Описать порядок вычислений

## Назначение

- Бизнес-цель: зафиксировать последовательность скидок, распределение дневной «без оплаты» по строкам и все точки округления для предварительного расчёта корзины.
- Требования: BL-1, FR-C2; дорожная карта этап 2; продолжение [docs/pricing-spec.md](../pricing-spec.md).
- Модуль: документация §3; код не менялся.
- Ответственный: агент.

## Входные условия

- FL-02-01/02 завершены (§1 словарь, §2 нормализация).
- Источник: `polevaya-kuhnya/js/state.js` — `getLineTotalsWithDiscount`, `calculateDayTotalAfterPercentage`, `resolveEffectiveDiscountClientForDay`, `getDayLinesWithDiscounts`, `calculateDayTotalsWithDiscount`, `calculateWeekTotalsWithDiscount`, `getCartTotalsForUserLimit`.
- Без runtime, без Dart-реализации, без согласования заказчиком.

## Оценка перед выполнением

- Объём: вся подзадача.
- Сложность: 6/10; трудоёмкость средняя, ≈6% этапа 2; LLM средняя.
- Основание: цепочка из 6+ функций с промежуточными округлениями и передачей убывающего остатка по строкам; риск случайно поменять порядок.

## Критерии завершения

Описаны: порядок применения процентной и дневной «без оплаты» скидок на уровне строки; распределение остатка дотации по строкам дня; агрегация дня/недели; сравнение с лимитом по `finalTotal`; полная таблица округлений. Согласование с серверным HTTP-пересчётом отмечено как открытое (не выдумано).

## Что сделано

В [docs/pricing-spec.md](../pricing-spec.md) добавлен **§3. Порядок вычислений и округление**:

- 3.1 строка: `round(price×qty)` → % скидка (round) → «без оплаты» (`min` с остатком) → round;
- 3.2 эффективная дневная дотация с учётом `MinimumPaymentAmount`;
- 3.3 последовательное распределение остатка по строкам дня в порядке меню;
- 3.4–3.5 агрегация дня/недели с round каждого из 4 полей;
- 3.6 сравнение с `Limit` по `finalTotal`, выбор день/неделя по `LimitPeriod`;
- 3.7 сводная последовательность сверху вниз;
- 3.8 таблица округлений.

Явно отмечено: согласование с сервером Zak при записи заказа не подтверждено runtime.
