# FL-03-04 — Создать форму входа

## Назначение

- Бизнес-цель: дать пользователю вход по коду и паролю через существующий API 1С с понятными состояниями формы.
- Требования: FR-A1, NFR-SEC-1/2/3, NFR-UI-4/6, FL-03-04 дорожной карты.
- Модуль: Flutter `features/auth`, маршрут `/sign-in`.
- Ответственный: агент.

## Входные условия

- Зависимые: FL-01-13 (SessionController и токен), FL-03-01–03 (модели и хранение), FL-02-17f (ошибки login/CORS).
- Контракт: `POST V1/User/login` с `login`, `password`, `deviceId`, `selfRegistration:true`; успешный ответ содержит токен. SessionController затем проверяет профиль по токену и сохраняет сессию. [Инвентарь API](FL-00-05.md), [профиль по токену](../profile-by-token.md), [архитектура](../../ARCHITECTURE.md).
- Окружение: Flutter 3.47.1, Web и Android AVD; iOS-тесты отложены пользователем.
- Ограничения: пароль не сохранять и не журналировать; не вызывать живой API, не создавать новые привязки/заказы/письма; тестировать сеть через MockClient. Zak и сайт не менять.

## Критерии завершения

Форма не отправляет пустые реквизиты; во время запроса блокирует повтор и показывает ожидание; пароль скрыт и очищается после отправки; ошибка видна без утечки секрета. Успех проходит через проверку токена существующим SessionController и router возвращает пользователя к безопасному `from`.

## Что сделано

- Сверены требования, существующий `SessionController.signIn`, router и форма ответа API.
- [LoginRepository](../../lib/features/auth/login_repository.dart) отправляет один `POST V1/User/login` с `selfRegistration:true` и проверяет наличие токена; профиль и сохранение токена остаются в `core/auth`. [LoginController](../../lib/features/auth/login_controller.dart) хранит только состояние загрузки/безопасной ошибки, блокирует повтор; код и пароль не входят в `LoginState`.
- [SignInPage](../../lib/features/auth/sign_in_page.dart) валидирует поля, скрывает пароль с доступным переключателем, очищает поле сразу после отправки и показывает ожидание/ошибку. Router использует её для `/sign-in`; после подтверждения сессии возвращает к безопасному `from` существующим правилом.
- Отказ API до сохранения токена оставляет `SessionStatus.signedOut`, а сбой хранилища по-прежнему даёт `unavailable`. Текст ошибки сервера напрямую в UI не выводится.
- Команды воспроизведения визуального smoke — в [Web/Android инструкции](../testing-web-android.md). Настоящие реквизиты не использовались.
- После FL-03-05 пароль остаётся в поле до ответа для менеджера паролей и очищается после завершения попытки; это заменяет исходную очистку сразу после отправки.
