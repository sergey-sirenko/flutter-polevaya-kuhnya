## Возможность одного запроса

Проверено по `CartEditController.begin`, `CartRepository`, серверным исходникам `Zak/Konf/CommonModules/ОбменHTTP/Ext/Module.bsl` и контрактам safe-order-retry/order-repeat. Сейчас подготовка выполняет четыре последовательных HTTP-запроса: basketstate → login (обновление профиля/заказов/условий) → menudates → basketstate. Сравнение первой/последней revision защищает от изменившегося в процессе чтения состава; последующая отправка basket также сверяет revision.

Один HTTP-запрос возможен при серверном расширении: вернуть в одном ответе актуальный профиль/условия, текущий состав выбранного дня, доступность и revision. Контекст сотрудника/владельца и доступ устройства должны проверяться сервером; клиент применяет ответ только для текущего владельца и текущей подготовки. Проверка согласованности чтения переносится внутрь серверного метода (revision до/после и повторная проверка доступности), защита revision при записи остаётся. Уже имеющийся ШаблонOrderRepeat использует похожие проверки внутри одного обращения, но возвращает исторический состав для повтора, поэтому им нельзя заменять подготовку текущего заказа.

Вариант для отдельной реализации: совместимое расширение basketstate с необязательным режимом подготовки, старый ответ без нового параметра сохранить; либо отдельный метод подготовки. Точный контракт/маршрутизацию утвердить перед изменением. Это один сетевой запрос, не один SQL-запрос 1С. Требуется изменение серверных исходников, затем загрузка пользователем в ИБ и обновление Flutter Repository/Controller. В этой задаче сервер не изменён и платформа 1С не запускалась; вывод о возможности основан на коде, не на измерении живого сервера.

## Что изменено

`ProfilePage`: centerTitle=true. `router.dart`: корзина дня сразу открывает /cart?prepare=<дата>; отдельный экран с датой и индикатором ждёт отображения кадра, затем запускает прежний begin. На успех выбранная дата синхронизируется и открывается прежний шаг: категории для пустого дня в узком окне, иначе корзина. Экран подготовки заменяется без дополнительного шага Back. При ошибке — пояснение/повтор/возврат. Уход со страницы отменяет применение ответа через существующий epoch контроллера и проверку текущего маршрута. Нет редактирования состава на экране подготовки.

Общий код Web/Android/iOS; Android не пересобран, iOS не запускалась. API/1С не изменены, реальных заказов/писем нет. Живая Web-приёмка выполняется пользователем после SSH, локальное моделирование её не заменяет.
