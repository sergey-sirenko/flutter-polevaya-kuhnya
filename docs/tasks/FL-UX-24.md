# FL-UX-24 — Сохранение изменений одним запросом

## Назначение и входные условия

Поручение 02.10.2026: настроить один запрос по результатам анализа четырёх обращений при обычном сохранении корзины. Контракт: [basket snapshot v1](../../../Zak/docs/basket-snapshot.md). FL-UX-18 подготовил общий формат снимка. Существующие изменения сохраняются.

## Оценка перед выполнением

Весь локальный пакет: сложность 5/10, трудоёмкость средняя, ≈85% этапа; LLM средняя. Серверный ответ после commit и безопасное применение в клиенте. Загрузка 1С пользователем — внешнее ожидание. Приёмка — отдельные ≈15%.

## План и критерии

- Контракт совместим со старыми клиентами; новый обычный basket запрашивает снимок.
- Подготовленная revision передаётся без menudates/basketstate; серверные проверки остаются в транзакции.
- Успешный ответ обновляет профиль/историю/даты без login. Квитанция сохраняет значение при ошибке чтения снимка.
- Повтор заказа сохраняет отдельную существующую проверку repeat; восстановление неизвестного исхода сохраняет basketresult и тот же ID/тело.
- Автотесты, analyze, локальная Web-сборка; документация и остановка.

## Ограничения

Без запуска 1С, изменения метаданных, живых заказов/писем, публикации и коммитов. Android не пересобирать, iOS не запускать. Серверный модуль загрузить до публикации клиента.
