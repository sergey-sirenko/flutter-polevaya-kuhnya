# FL-03-05 — Подключить менеджеры паролей

## Назначение

- Бизнес-цель: дать менеджеру паролей распознавать код входа и пароль в форме Flutter.
- Требования: FR-A7 и FL-03-05 дорожной карты.
- Модуль: Flutter `features/auth`, маршрут `/sign-in`.

## Входные условия

- Зависимость: FL-03-04; успешный вход подтверждает существующий `SessionController`.
- Контракт: поля кода входа и пароля объединены `AutofillGroup`, имеют подходящие `autofillHints`; сохранение пары предлагается только после подтверждённого входа. Ошибка и уход со страницы не должны предлагать сохранение.
- Окружение: Flutter 3.47.1, локальные Web и Android; iOS-тестирование отложено пользователем.
- Ограничения: секреты не входят в состояние, документы или журналы; живой API для этой проверки не требуется.

## Критерии завершения

Форма предоставляет платформе назначение обоих полей. Контекст сохранения завершается только после подтверждённого входа; отказ и закрытие формы не сохраняют неуспешную пару. В Web и Android проверено доступное поведение; если менеджер не настроен, это явно отделено от end-to-end приёмки.

## Что сделано

- [SignInPage](../../lib/features/auth/sign_in_page.dart): поля кода входа и пароля входят в один `AutofillGroup` с `AutofillHints.username` и `AutofillHints.password`. Уход со страницы отменяет контекст. После подтверждённой сессии форма вызывает `TextInput.finishAutofillContext(shouldSave: true)` и очищает пароль; после ошибки вызывает `shouldSave: false` и также очищает поле.
- [LoginController](../../lib/features/auth/login_controller.dart) возвращает результат подтверждённой сессии форме, не помещая реквизиты в состояние.
- [Widget-тесты](../../test/features/auth/sign_in_page_test.dart) проверяют подсказки, результат входа, отказ и уход с формы. Проверка Web и Android описана в [инструкции](../testing-web-android.md).
