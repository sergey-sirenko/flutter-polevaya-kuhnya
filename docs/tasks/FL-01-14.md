# FL-01-14 — Подготовить тестовые ответы

## Назначение

- Бизнес-цель: дать воспроизводимые обезличенные ответы для локальных проверок клиента без рабочей 1С.
- Требования ТЗ: API-1, API-3, API-4, API-9, NFR-SEC-4; [этап 1 дорожной карты](<../../Дорожная карта.md>).
- Модуль: `test/fixtures/api`, тесты транспорта и сессии.
- Ответственный: Codex.

## Входные условия

- Зависимые задачи: FL-01-12/13 завершены.
- Контракты: [указатель API](../api-1c.md), [инвентарь FL-00-05](FL-00-05.md), [меню FL-00-10](FL-00-10.md), [заказы FL-00-11](FL-00-11.md), [архитектура](../../ARCHITECTURE.md).
- Окружение: локальные JSON и MockClient; реальная 1С не вызывается.
- Ограничения: не сохранять реальные пароли, токены, профили и заказы; черновые формы не объявлять утверждённым контрактом. Сборки, запуск приложения и публикация вне задачи.

## Оценка перед выполнением

- Оцениваемый объём: вся FL-01-14.
- Сложность: 4/10.
- Трудоёмкость: средняя; ≈4% трудозатрат полного этапа 1.
- Рекомендуемая категория LLM: средняя.
- Основание: нужно согласовать несколько форм ответов и статусы ошибок с действующим транспортом, сохранив границу между наблюдением и целевым контрактом. Внешнее ожидание уточнений API учитывается отдельно.

Фикстуры читаются локально; покрыты успех, пустые данные, старая/новая ошибка и истёкшая сессия. Для каждого ответа известны маршрут, HTTP-код и доказательность. Проверки выполняются без рабочей 1С.

Корзина намеренно не имитируется до контрактов сумм и повторов FL-02-15/16.

[Тест](../../test/core/api/api_fixtures_test.dart) читает файлы и подаёт их действующему ApiClient через MockClient. Он проверяет пригодность JSON, успешный и пустой ответы, различие старого 400, ошибки с кодом, 500 и целевого 401. [API-указатель](../api-1c.md) теперь ссылается на набор и его ограничения. Код приложения и соседние проекты не менялись.
