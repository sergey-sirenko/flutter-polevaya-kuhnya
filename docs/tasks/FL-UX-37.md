# FL-UX-37 — Продолжение только набора с несохранёнными изменениями

## Назначение
Разобрать сообщение пользователя: после закрытия вкладки, открытия сайта и «Заказать обед» показан сохранённый набор; продолжение открывает корзину без дней с «!».

## Входные условия и оценка
Снимок и сообщение пользователя, текущие исходники +76. Диагностический шаг: сложность 3/10, трудоёмкость низкая, LLM средняя; нужно отличить неизменённый снимок от потери несохранённых правок. Отдельная UX-задача вне этапа, доля старого этапа не назначается. Тесты/превью не запускать по ограничению; браузерное хранилище пользователя не исследовано.

## Установлено
- CartEditController._prepare при создании нового набора записывает CartWorkSnapshot в CartWorkStore сразу, до редактирования. quantities исходного снимка совпадают с originals, changedDates пуст.
- При запуске контроллер читает этот снимок; recovery != null считается сохранённым набором независимо от changedDates. Баннер показывает «Есть сохранённый набор.» даже при отсутствии локальных изменений.
- CartWorkSnapshot.changedDates и CartEditState.changedDates сравнивают количества с исходным составом. В cart_page.dart «!» появляется только для changedDates; наличие recovery само по себе знак не добавляет.
- resume передаёт сохранённый снимок в _prepare; при успешной проверке исходных версий восстанавливаются именно work.quantities, а не новый серверный состав. Нельзя по текущему снимку пользователя утверждать, что существующие несохранённые правки потеряны.
- Изменения draft наблюдаются listener и сохраняются через persistNow/CartWorkQueue; эта запись асинхронна. Факт выполнения последней записи до закрытия конкретной вкладки не проверен. Называть это доказанной причиной потери нельзя.
