# FL-02-13 — Зафиксировать отсутствие сброса пароля

## Назначение

- Бизнес-цель: закрепить решение пользователя об отсутствии сброса общего пароля организации и не обещать неподдерживаемый сценарий в браузере.
- Требования ТЗ: FR-A3 исключено решением пользователя 27.09.2026; API-2 без recovery; NFR-SEC-1/4 сохраняются для входа и сессии.
- Модуль: документы Flutter, `/reset-password` в будущей FL-03-11; сервер Zak не меняется.
- Ответственный: агент; решение о продуктовой границе принято пользователем.

## Входные условия

- FL-00-08: готового HTTP-метода восстановления нет. Организационный логин/пароль общий для сотрудников; персональная почта сотрудника не даёт полномочия менять пароль организации.
- FL-02-12: пользователь сообщил о загрузке изменений Zak в рабочую ИБ для тестов. Сообщение фиксирует загрузку, но не доказывает живую приёмку `context_v1` или точную версию загруженных модулей.
- Решение пользователя: «сброс пароля не предусмотрен». API, письма и тестовые записи для восстановления не нужны.
- Сохранить незавершённые изменения FL-02-12 в Zak/Flutter и пользовательские изменения сайта; отдельный Git-коммит пока не делать.

## Оценка перед выполнением

- До решения пользователя оценивалась вся серверная подзадача: 8/10, высокая, ≈10% этапа 2, LLM сложная.
- После решения оцениваемый остаток — документальное исключение: сложность 2/10; трудоёмкость низкая, ≈1% этапа 2; LLM лёгкая.
- Основание изменения: не требуется проектировать проверку личности, код и серверный сброс; нужны согласование требований, ссылок и будущей страницы. Внешнего ожидания больше нет.

## Критерии завершения

- `/reset-password` определён как информационная страница. Форма пароля, код, ссылка подтверждения и серверный вызов отсутствуют.
- Параметры ссылки, похожие на подтверждение, не отображаются и не обрабатываются. Недействительного подтверждения нет как состояния сценария.
- Решение пользователя отражено в требованиях; реализация страницы отложена до FL-03-11, что отмечено отдельно.

## Что сделано

- Подтверждено по исходникам и FL-00-08: в `User` HTTP нет метода восстановления; `/reset-password` пока лишь маршрут Flutter.
- Пользователь ответил: «сброс пароля не предусмотрен». Это отменяет исходное требование FR-A3 о восстановлении, но не меняет вход, регистрацию, смену email, удаление аккаунта и обработку истечения сессии.
- Для FL-03-11 закреплён сценарий: из входа доступна ссылка на `/reset-password`; страница сообщает, что сброс недоступен, и предлагает обратиться к ответственному представителю организации или поддержке по вопросу выданных реквизитов, без обещания их замены. Прямой Web-адрес открывается без авторизации; неизвестные параметры адреса не выводятся, не сохраняются и не отправляются в Zak. Возврат ведёт ко входу.
- Поскольку запрос восстановления и токен подтверждения не создаются, нет состояний «недействительный», «просроченный» и «уже использованный» код. При посещении адреса с такими параметрами показывается та же информационная страница без разбора значения.
- Уточнены ТЗ, дорожная карта, матрица требований, ARCHITECTURE и API-указатель. Код Zak/Flutter/сайта не менялся.
