# FL-02-17c — Согласовать обработку ошибок во Flutter

## Назначение

- Бизнес-цель: клиент различает истечение сессии, сбой привязки устройства и бизнес-отказ по контракту api-errors.
- Требования ТЗ: API-9, NFR-SEC-4; §5.2 дорожной карты.
- Модуль: `lib/core/api`, `lib/core/auth`.
- Ответственный: агент.

- Зависимые: FL-02-17a/b; транспорт FL-01-12; сессия FL-01-13.

- Ограничения: без обязательного живого API; POST без автоповтора; экранные сценарии features — вне объёма.

## Критерии завершения

Транспорт отличает 401, переходный 400+session codes, 403 device_mismatch/session_unbound (очистка) и access_denied (без автоочистки). Неизвестный код и старый 400 без кода не очищают токен. POST не повторяется автоматически.
