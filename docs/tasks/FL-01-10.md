# FL-01-10 — Настроить маршрутизацию

## Назначение

- Бизнес-цель: адресуемые страницы с едиными правилами доступа и сохранением запрошенного адреса.
- Требования ТЗ: раздел 4.1, NFR-UI-4, NFR-SEC-4; [архитектура](../../ARCHITECTURE.md), разделы 4–5 и ADR-8; [этап 1](<../../Дорожная карта.md>).
- Модуль: `app/router.dart`, конфигурация/состояние сессии и `core/platform/distribution.dart`.
- Ответственный: Codex.

## Входные условия

- Зависимые задачи: FL-01-08/09 завершены. Настоящее восстановление и хранение сессии — FL-01-13 и этап 3.
- Нужные контракты и решения: [FL-00-10](FL-00-10.md) различает публичный файл меню и защищённые даты заказа. Существующий сайт разрешает гостевой просмотр меню (`polevaya-kuhnya/docs/product-guide.md`, раздел «Просмотр меню»); профиль/заказы требуют входа. Новый API-контракт не вводится.
- Окружение: Flutter 3.47.1, Dart 3.13.1, go_router 18.0.1, Riverpod 3.4.3. Git `master`, без коммитов/remote.
- Ограничения: проверки без живой 1С и сети приложения; сборки/браузерная приёмка и публикация вне задачи. Незаполненные страницы — явные заглушки без форм, данных и имитации успешного входа.

## Правила маршрутизации до реализации

| Адрес/состояние | Поведение |
|---|---|
| `/`, `/about`, `/delivery`, `/how-to-order`, `/contacts`, `/install` | Публичные страницы |
| `/sign-in`, `/sign-up`, `/reset-password` | Публичные точки входа в будущие сценарии авторизации; reset-password не перенаправляется из-за уже открытой сессии |
| `/menu` | Публичный просмотр; доступные дни и операции заказа будут проверяться отдельно по контракту |
| `/cart`, `/orders`, `/profile` | Только подтверждённая сессия |
| Гость на защищённом адресе | `/sign-in?from=…`, исходный локальный адрес с query/fragment сохраняется |
| Восстановление сессии / ошибка её проверки | Защищённое содержимое закрыто; адрес сохраняется; ошибка связи не считается выходом |
| Подтверждённый вход на `/sign-in` | Возврат на известный локальный адрес из `from`, иначе `/menu`; внешние и циклические адреса не принимаются |
| Неизвестный адрес | Отдельный экран «Страница не найдена», без автоматического открытия защищённого содержимого |
| Обычный старт | Web `/`, Android/iOS `/menu`; явный Web-адрес имеет приоритет |

Состояние сессии задаётся ручным Riverpod provider. До FL-01-13 источник возвращает отсутствие входа; фиктивного токена/пользователя нет. В тестах состояния подменяются. Router реагирует на изменения без пересоздания. Платформенные условия находятся только в distribution.dart. Для Web используется path-стратегия SDK; серверная отдача index.html по прямым маршрутам проверяется в FL-06-14.

## Что сделано

Прочитаны правила, текущая карточка, ТЗ/архитектура, аудит меню и исходники установленного go_router. Правила доступа записаны до кода.

- [router.dart](../../lib/app/router.dart) — единственный router и набор адресов. Сопоставление регистрозависимое, защита опирается на совпавший маршрут, а не сырой URL. `from` принимается только для известных локальных страниц, кроме auth-маршрутов; неоднозначный/внешний адрес заменяется на `/menu`.
- [session_status.dart](../../lib/core/auth/session_status.dart) — четыре состояния доступа; сейчас источник всегда возвращает `signedOut`. Нет хранилища, токена, учётной записи или кнопки фиктивного входа. Проверка переходов использует только тестовый Notifier.
- Защищённый экран дополнительно слушает состояние: восстановление/ошибка закрывают его даже при неизменном URI. При выходе из стека с защищённой основой router переводит на вход и снимает прежние страницы; Back не возвращает личный экран.
- [distribution.dart](../../lib/core/platform/distribution.dart) — ADR-8 и path-стратегия с сохранением fragment. `initialLocation` не переопределяет явный адрес платформы. Для разработки на неподдерживаемой native-платформе используется `/`; новых desktop-целей нет.
- `main.dart` создаёт ProviderScope и передаёт проверенный AppConfig; `MaterialApp.router` получает router через provider. [RoutePage](../../lib/app/route_page.dart) явно сообщает, что будущие разделы недоступны, а неизвестный путь имеет отдельное сообщение. Метка test сохранена на всех экранах. На главной действует переход «Заказать обед» к `/menu`.
- SDK-пакет `flutter_web_plugins`, уже находившийся в lockfile транзитивно, объявлен прямой зависимостью; версии пакетов не изменились. Пустых feature-каталогов и генераторов нет.

Справка по API: [перенаправления go_router](https://pub.dev/documentation/go_router/latest/topics/Redirection-topic.html), [Web URL strategy Flutter](https://docs.flutter.dev/ui/navigation/url-strategies); поведение также сверено с локальными исходниками go_router 18.0.1 и установленного SDK. Серверный fallback на index.html при path-стратегии ещё не настраивался.
