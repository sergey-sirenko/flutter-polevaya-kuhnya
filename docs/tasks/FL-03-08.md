# FL-03-08 — Реализовать начало регистрации

## Назначение

- Цель: открыть ввод ФИО/email только после ответа 1С о необходимости регистрации и начать `context_v1` без сохранения пароля.
- Требования: FR-A2, NFR-SEC-1, FL-03-08 дорожной карты.
- Модуль: Flutter `features/auth`, `/sign-up`.

## Входные условия

- Зависимости: FL-02-12 (серверный контекст), FL-03-03 (deviceId), FL-03-04 (паттерн формы входа).
- Контракт: [Zak self-registration 1.1](../../../Zak/docs/self-registration.md). `registrationstatus` с `login/password/deviceId` определяет `registration_required`; `registrationstart` добавляет `fullName/email/registrationMode: context_v1`, при успехе возвращает `code_sent` и `requestId`. Повтор/подтверждение — FL-03-09.
- Ограничения: Zak и сайт не меняются; реальные письма не отправляются в локальных тестах. Web/Android проверяются в доступном объёме, iOS отложена пользователем.

## Оценка перед выполнением

- Вся FL-03-08: сложность 8/10; трудоёмкость высокая, ≈10% этапа 3; LLM сложная.
- Основание: два шага API, блокировки и границы хранения пароля. Работа живого серверного `context_v1` не подтверждена и учитывается отдельно.

## Критерии завершения

ФИО/email доступны только после `registration_required` от 1С. `registrationstart` посылает `context_v1`; при `code_sent` хранит только `requestId` в памяти формы и очищает пароль. Блокировки и временные отказы не открывают следующий шаг. Повтор и подтверждение не реализуются до FL-03-09.

## Состояние

- Работа: завершена в доступном локальном объёме.
- Реализация: `registrationstatus` и `registrationstart` подключены через Repository → Controller → UI; форма ФИО/email открывается только после `registration_required`.
- Проверка: 180 тестов и analyze прошли; Web и Android debug APK собраны с синтетическим `.invalid` API. Живой поток 1С и доставка письма не проверялись.
- Выпуск: не выполнялся.

## Что сделано

- Сверены контракт и существующая форма входа. Правки серверной части Zak не потребовались.
- [RegistrationRepository](../../lib/features/auth/registration_repository.dart) выполняет read-only `registrationstatus` и `registrationstart` с `context_v1`, проверяет `ready`/`registration_required`/`code_sent` и UUID `requestId`. Старые клиенты не менялись.
- [RegistrationController](../../lib/features/auth/registration_controller.dart) получает постоянный `deviceId`, блокирует повторную отправку и переводит коды отказа в безопасные сообщения без отображения серверных деталей.
- [SignUpPage](../../lib/features/auth/sign_up_page.dart) показывает реквизиты, затем ФИО/email только по ответу 1С. После ответа `registrationstart` пароль очищается; при отказе для новой попытки он вводится заново. `requestId` остаётся только в памяти открытой формы и не выводится. Маршрут `/sign-up` подключён к router, ссылка добавлена из входа.
- Поскольку FL-03-09 ещё не начата, ввод кода/повтор не добавлены. Экран после `code_sent` подтверждает только принятие запроса на отправку; доставку письма он не утверждает.
