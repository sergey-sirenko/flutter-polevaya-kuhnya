# FL-03-03 — Реализовать идентификатор устройства

## Назначение

- Бизнес-цель: постоянный идентификатор устройства для входа и восстановления сессии без ненужной новой привязки после перезапуска.
- Требования: FL-03-03 дорожной карты, C-07/C-08, ADR-3, NFR-SEC-3.
- Модуль: Flutter `core/auth/SessionStorage.deviceId`.
- Ответственный: агент.

## Входные условия

- Зависимые задачи: FL-01-13 (реализация и клиентское решение), FL-03-02 (хранилище и доступные платформы).
- Контракт: постоянный UUID v4 без `New3_`, отдельный ключ secure storage по окружению/API; выход удаляет токен, не ID. Миграция старого Web `DEVICE_ID` относится к FL-08-04. [Источник решения](FL-01-13.md), [архитектура](../../ARCHITECTURE.md), [C-07/C-08](FL-00-15.md).
- Окружение: Windows, Web localhost, Android 15 AVD; iOS runtime недоступен локально.
- Ограничения: синтетический ID не выводить в документацию/логи; рабочий API и 1С не вызываются; исходники Zak и сайт не меняются.

## Оценка перед выполнением

## Критерии завершения

Идентификатор соответствует UUID v4 без префикса, повторно используется после выхода и перезапуска на доступных платформах. Повреждённое значение не заменяется молча, чтобы не создать новую привязку. Недоступная iOS-проверка отмечается отдельно.

## Состояние

- Работа: завершена в доступном объёме; iOS runtime остаётся непроверенным.
- Реализация: генерация и сохранение существуют с FL-01-13; проверка сохранённого ID ужесточена до UUID v4, включая пустое значение.

## Что сделано

- Сверены клиентское решение, хранение по окружению/API и вызовы `deviceId` при входе/восстановлении.
- `SessionStorage.deviceId` отвергает пустой, повреждённый, не-v4 и `New3_` ID без молчаливой замены. Unit test проверяет, что повреждённое значение сохраняется и ошибка сообщается без генерации новой привязки.
- Добавлена [платформенная проба](../../integration_test/device_id_probe.dart): сравнивает ID с сохранённым в secure storage маркером после перезапуска, не показывает ID на экране и удаляет маркер после сравнения. Она также проверяет формат и сохранность при удалении токена.
- Пошаговое воспроизведение среды и Web/Android сценариев записано в [локальной инструкции](../testing-web-android.md) после вопроса пользователя.
- В архитектуре исправлена устаревшая запись ADR-3: открыта миграция старого ID, а не выбор формата нового ID.
