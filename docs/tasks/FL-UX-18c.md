## Реализация

`OrderSnapshot` полностью проверяет профиль/условия/историю, доступность, states, schemaVersion/scope и календарные даты до применения. Repository вызывает только POST Orders/snapshot для подготовки. `CartEditController.begin` проверяет день/меню/состав/владельца/операцию, затем синхронно применяет профиль, даты, состав и revision; не обновляет токен и не меняет поколение сессии. `SessionController.applyProfileSnapshot` закрепляет scope в пределах поколения. `MenuAllowedDatesController.applySnapshot` отменяет применение прежних результатов чтения дат. Ошибки сохраняют черновик и ранее применённые данные.

`basketstate` остаётся для существующих проверок отправки/повтора, не вызывается подготовкой. Basket и защита неизвестного исхода/версии приложения не изменены. Отсутствующий серверный метод приводит к ошибке подготовки, fallback отсутствует.
