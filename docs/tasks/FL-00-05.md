## Что сделано

### Источники и область

Метаданные [HTTP-сервиса Obmen](../../../Zak/Konf/HTTPServices/Obmen.xml) задают шаблоны `/V1/User/{ИмяМетода}`, `/V1/Orders/{ИмяМетода}` и `/V1/SBP/{ИмяМетода}`. User принимает POST/GET/OPTIONS, Orders — POST/OPTIONS, SBP — POST/GET/OPTIONS. В таблице ниже перечислены операции, которые фактически вызывает сайт. Существующие endpoints активации, теста, SBP и серверный `registrationstatus` не вызываются просмотренными клиентами сайта и в контракт сайта не включены. Удаление аккаунта и восстановление пароля среди вызовов и обработчиков просмотренного HTTP-сервиса не найдены; их аудит остаётся FL-00-08/09.

Меню сайта загружается из runtime-файла `data/dishes.json`, а изображения — отдельными файлами. Это не endpoint HTTP-сервиса Zak и не включено в таблицу ниже.

### Черновой инвентарный контракт

База URL сервиса по конфигурации и текущему клиенту: `https://hleb-sol.su/Zakaz_http/hs/Obmen`. Записи ниже отражают исходники, не подтверждены живыми ответами сервера и не являются утверждённым контрактом Flutter.

| Операция сайта | Запрос | Наблюдаемый успех | Известные ошибки/ограничения |
|---|---|---|---|
| Вход `User/login` | POST JSON: `login`, `password`, `deviceId`; сайт добавляет `selfRegistration: true`. Повторный профиль: `token`, `deviceId`. Сервер также читает необязательный `orderdate`. | HTTP 200; `{success:true,message,token,user}`. В `user` код формирует имя, email, phone, login, employee, скидки, лимит, минимальные суммы и массив `order`. | Общий HTTP 400 `{success:false,error}` при пустом/неверном JSON, отсутствии полей, неверном токене/пароле, неизвестном логине или запрете доступа. Саморегистрация может вернуть свой `code`; общий формат см. ссылку на серверный контракт. Внешняя проверка не выполнялась. |
| Доступные дни `Orders/menudates` | POST JSON: `token`. | HTTP 200; `{success:true,message,menudates}`. | HTTP 400 с `success:false,error` при пустом/неверном JSON, отсутствии/недействительности токена. |
| Отправка корзины `Orders/basket` | POST JSON: `token`, `order[]`; каждый день содержит `date` и `dishes[]` с `dish`, `name`, `quantity`, `DiscountClient`. Клиент включает разрешённые дни с пустым списком блюд. Сервер читает также необязательный `orderdate` для выборки ответа; сайт его не отправляет. | HTTP 200; `{success:true,message,order}` с повторно загруженными заказами. | HTTP 400 с `success:false,error`: неверный JSON/токен, нет `order`, блюдо не найдено или заказ не принят. Вызов может менять реальные заказы, поэтому в этой задаче не выполнялся. |
| Контактная форма `User/message` | GET query-поля `name`, `phone`, `email`, `message`; сайт кодирует их через `URLSearchParams`, email/message по умолчанию пусты. | При успехе сервер возвращает общий ответ `{success:true,message}` (HTTP 200). | Клиент сводит сетевые/JSON/неуспешные ответы к сообщению «Сообщение не доставлено. Попробуйте позже». В GET-обработчике при неуспехе постановки письма ответ не назначается; фактический HTTP-ответ в этом пути по исходникам не установлен. Вызов может поставить письмо в очередь, поэтому не выполнялся. |
| Саморегистрация `User/registrationstart`, `registrationresend`, `registrationconfirm` | POST JSON с `login`, `password`, `deviceId`; start дополняет `fullName`, `email`; resend — `requestId`; confirm — `requestId`, `verificationCode`. Начало потока инициирует ответ входа `registration_required`. | Общая форма `{success,code,message,error}`; start/resend возвращают `code_sent`, `requestId`, `retryAfter`, `expiresIn`; confirm — `registered`. | HTTP 400 для известных бизнес-ошибок; детальные коды и ограничения описаны в каноническом [контракте Zak](../../../Zak/docs/self-registration.md). Изменения в базе/доставка почты не проверялись. |
| Смена почты `User/emailchangestatus`, `emailchangestart`, `emailchangeresend`, `emailchangeconfirm` | POST JSON, все операции: `token`, `deviceId`; start — `email`; resend — `requestId`; confirm — `requestId`, `verificationCode`. | Общая форма `{success,code,message,error}`; status — `email_change_status`, `email`, `canChangeEmail`; start/resend — `code_sent`, `requestId`, `retryAfter`, `expiresIn` (если адрес прежний, `email_unchanged`); confirm — `email_changed`, `email`. | HTTP 400 для бизнес-ошибок; коды доступа, срока, повтора и занятости адреса описаны в [контракте Zak](../../../Zak/docs/email-change.md). Отправка письма/изменение данных не проверялись. |

Для стандартных операций `ОтветОшибка` возвращает HTTP 400 и JSON `{success:false,error}`; неизвестный метод также возвращает HTTP 400. Обёртки User POST и Orders POST превращают необработанное исключение в HTTP 500 с `{success:false,error}`. Это описание исходников, не обещание единого формата на всех маршрутах.

### Наблюдения и расхождения

- Комментарий в модуле HTTP-сервиса Zak заявляет `/api/orders/create` и `/api/orders/list`, но метаданные и диспетчер реально маршрутизируют только `/V1/Orders/basket` и `/V1/Orders/menudates`. Комментарий выглядит устаревшим; в качестве маршрутов его не использовать.
- Обработчик `User/login` добавляет поле `token` в ответ; новый токен создаётся только в ветке входа по логину/паролю. В ветке обновления по `token` он повторно не создаётся; клиент сайта сохраняет переданный токен, если ответ не содержит нового. Детальная семантика сессии и устройства — FL-00-06.
- CORS helper в исходнике выставляет `Access-Control-Allow-Origin: *` вместе с `Access-Control-Allow-Credentials: true`. Это только статическое наблюдение; пригодность для браузера и поведение рабочего API с origin `https://flutter-test.obedmoscow.ru` здесь не проверялись, проверка отнесена к FL-00-14d.
- Форматы и коды регистрации/email дополнительно сверены с поставляемыми контрактами Zak. Их фактические HTTP-ответы не запрашивались.
