# FL-02-04 — Описать ограничения заказа

## Назначение

- Бизнес-цель: зафиксировать правила минимума заказа и лимитов (день/неделя/месяц), включая учёт уже проведённых заказов на сервере и отличия от клиентского предпросмотра.
- Требования: BL-1, FR-C2; дорожная карта этап 2; продолжение [docs/pricing-spec.md](../pricing-spec.md).
- Модуль: документация §4; код не менялся.
- Ответственный: агент.

## Входные условия

- FL-02-01…03 завершены.

- Без runtime API и без согласования заказчиком.

## Что сделано

В [docs/pricing-spec.md](../pricing-spec.md) **§4**:

- минимум: клиент (по дням корзины, эффективный порог при дотации) vs сервер (`НедостаточнаяСуммаЗаказа`); HTTP `ЗаписатьЗаказ` статически **не** вызывает серверный минимум, SOAP — вызывает;
- лимит клиента: только корзина сессии, периоды день/неделя;
- лимит сервера: день/неделя/месяц; для недели/месяца (и сотрудника — для всех периодов) суммируются другие проведённые заказы периода;
- зафиксированы асимметрии в BSL (скидки то учитываются, то закомментированы; сообщение сотрудника всегда «за неделю»);
- календарная неделя 1С ≠ неделя меню UI.
