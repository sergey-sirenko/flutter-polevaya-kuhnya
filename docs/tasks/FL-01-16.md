## Что сделано

Сверены настройки test и Android. Release Android пока использует debug signing и временный applicationId.

Первая Web-компиляция выявила ошибку в [distribution.dart](../../lib/core/platform/distribution.dart): `PathUrlStrategy(null, true)` принимался native-заглушкой SDK, но Web требует ненулевой PlatformLocation. Передан `BrowserPlatformLocation()`; сохранение fragment оставлено. Финальная release Web-сборка успешна.

Первая Android-сборка упала в Kotlin incremental cache трёх плагинов: `this and base files have different roots` для Pub cache на C: и проекта на E:. В [gradle.properties](../../android/gradle.properties) отключена инкрементальная компиляция Kotlin; это снижает скорость повторной Kotlin-компиляции, но устраняет установленную причину сбоя без переноса кэшей. Параметр описан в [документации Kotlin](https://kotlinlang.org/docs/gradle-compilation-and-caches.html).

В [release-манифест](../../android/app/src/main/AndroidManifest.xml) добавлено INTERNET: до исправления разрешение было только в debug/profile, отсутствовало и в объединённом release-манифесте. Требование для сетевого приложения — [документация Flutter](https://docs.flutter.dev/deployment/android). Наличие разрешения в готовом APK подтверждено `aapt`.

Gradle автоматически установил Android Platform 35 revision 2 и CMake 3.22.1 в активный SDK по ранее принятым лицензиям. Основной compileSdk/targetSdk приложения — 36.

## Настройка Codemagic — шаги пользователя

Агент не коммитит и не пушит без явного разрешения. Ниже — минимальный порядок, чтобы Codemagic увидел `codemagic.yaml` и собрал iOS.

### 1. Первый коммит (локально)

Репозиторий сейчас: ветка `master`, **коммитов нет**, remote нет. Нужен хотя бы один коммит с проектом, включая корневой `codemagic.yaml`.

- Либо разрешите агенту: «сделай первый коммит» (push отдельно).
- Либо выполните коммит сами.

### 2. Удалённый Git (origin)

Codemagic клонирует код только из remote. Выберите хостинг и создайте пустой репозиторий (без README, если хотите чистый push):

- **GitHub** (предпочтительно по [документации Codemagic](https://docs.codemagic.io/getting-started/adding-apps/)), **GitLab**, **Bitbucket** или другой URL по SSH/HTTPS.
- Сообщите агенту URL origin и разрешите `git remote add` + `git push -u origin master`, либо сделайте push сами после коммита.

Публикация сайта / магазинов этим шагом **не** выполняется — только размещение исходников для CI.

### 3. Аккаунт и приложение в Codemagic

1. Зарегистрируйтесь / войдите на [codemagic.io](https://codemagic.io).
2. **Add application** → подключите Git-провайдер (для GitHub — приложение «Codemagic CI/CD» и доступ к нужному репозиторию).
3. Выберите репозиторий Flutter; тип проекта — Flutter / или «configured with codemagic.yaml».
4. Убедитесь, что в настройках приложения используется **codemagic.yaml** (не только Flutter Workflow Editor): файл уже в корне репозитория.
5. Для **App Preview** (браузерный симулятор) нужна **команда (team)** Codemagic; на Pay as you go — включение App Preview и пробные минуты по [документации](https://docs.codemagic.io/flutter-distributing/app-preview/). Без команды сборка `.app` всё равно возможна, Quick Launch может быть недоступен.

Сообщите агенту: аккаунт создан, приложение добавлено, billing/team есть или нет.

### 4. Запуск workflow

1. В Codemagic: **Start new build**.
2. Ветка: `master` (или та, куда запушили).
3. Workflow: **`ios-simulator-test`** / «iOS Simulator (test)».
4. Дождитесь завершения: analyze + тесты + `flutter build ios --debug --simulator`.
5. Среди артефактов должен появиться **`Runner.app`**.

При ошибке сборки пришлите лог (или ссылку) — агент разберёт и поправит yaml/проект без повторного гадания.

### 5. App Preview (если команда включена)

1. В обзоре успешной сборки у артефакта `.app` нажмите **Quick Launch**.
2. В браузере откроется симулятор с установленным приложением (сессия до ~20 мин).
3. Это проверка UI на симуляторе, не приёмка на физическом iPhone и не App Store.
