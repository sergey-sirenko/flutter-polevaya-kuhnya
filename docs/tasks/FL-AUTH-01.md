## Что сделано и вывод

Ошибки, требующей изменения кода в проверенном сценарии, не обнаружено. Повторно используются действующие реквизиты организации и та же личная почта. На новом устройстве нужна самостоятельная привязка через подтверждение почты; одноразовый код из первого письма не является постоянным кодом входа.

| Сценарий | Результат проверки исходников |
|---|---|
| Вход на новом устройстве | Flutter передаёт свой постоянный UUID и selfRegistration=true. Zak возвращает registration_required для неподключённого устройства. Интерфейс показывает «Для этого устройства требуется регистрация», доступна ссылка «Регистрация». Автоматического перехода нет. |
| Та же почта в той же организации | ПодтвердитьСаморегистрацию сравнивает НРег(СокрЛП(email)) и владельца. Один найденный сотрудник используется повторно; его ФИО не меняется. Новый создаётся только при отсутствии совпадения. |
| Подключение второго устройства | Набор ИдКлиентов отфильтрован по организации и новому UUID: запись первого устройства не заменяется. |
| Независимость входов | СеансыПользователей содержит измерения Пользователь, Сотрудник, ИдКлиента; Токен — ресурс. Второй UUID образует другой ключ. Выход по токену отзывает только этот ключ. Это зависит от сохранности измерения ИдКлиента в загруженной ИБ. |
| Старый одноразовый код/requestId на втором устройстве | КонтекстСаморегистрации и ЗапросПодтверждения проверяют UUID устройства; требуется новое письмо. После успешного подтверждения хеш очищается. |
| Одновременные подтверждения одной почты | Поиск сотрудника и запись привязки выполняются в транзакции под исключительными блокировками справочника сотрудников/регистра устройств; состояние устройства повторно проверяется после ожидания. Поведение платформы при конкуренции не запускалось. |
| Ограничения | Блокировка организации/сотрудника и неоднозначная почта не обходятся. Общие лимиты почты сохраняются: минимум минута между письмами и не более пяти за час. |

История заказов читается по организации и текущему сотруднику, а не по устройству: один сотрудник получает ту же серверную историю. Локальные черновики между устройствами автоматически не синхронизируются; это не проверка синхронизации корзины.
