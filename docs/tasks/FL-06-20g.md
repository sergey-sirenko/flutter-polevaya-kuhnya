# FL-06-20g — Версии фото меню

## Назначение

- Бизнес-цель: обновлять одноимённое фото по сигналу `photo_version`, закрыть клиентскую часть W10.
- Требования: FR-M4; решение владельца в FL-06-20f.
- Модуль: общее меню Web, Android и iOS.
- Ответственный: LLM.

## Входные условия

- Зависимости: FL-06-20f, контракт представления v0.3 в FL-04-16.
- Контракт дополнения v0.4 зафиксирован ниже до реализации.
- Источник меню/фото: `https://obedmoscow.ru/data/` для всех клиентов.
- Без публикации, изменений Zak, реальных заказов и iOS-тестирования. Живую Web-приёмку выполняет пользователь после отдельной выкладки.
- До работы сообщено: для появления поля в рабочем JSON требуется точечное добавление `photo_version` в выгрузку `dishes.json` Zak; отдельного поручения на сервер нет.

## Оценка перед выполнением

- Вся клиентская подзадача: сложность 5/10; трудоёмкость средняя, ≈4% этапа 6; LLM средняя.
- Основание: необязательное поле, постоянное хранение версий, согласованные URL и проверки смены/отсутствия версии. Работа по выгрузке Zak и внешняя ручная приёмка в оценку не входят.

## Контракт представления v0.4

- Необязательное `photo_version` у блюда относится к `imagePath`; у категории — к `categoryimagePath`. Строка после trim или целое число преобразуется в строку. Отсутствие, null и пустая строка означают отсутствие сигнала версии. Объекты, массивы, bool и дробные числа отклоняются как неверный формат меню.
- Сервер меняет значение при замене содержимого JPG с прежним именем. Это непрозрачный идентификатор, клиент не сравнивает его как число/дату. Одно имя фото в одном файле должно иметь одну явную версию; конфликт отклоняется до записи локальных версий.
- Реестр клиента привязан к полному адресу источника данных и имени фото, общий для публичного меню всех пользователей. Сохраняются только имена и версии, без цен/меню/токенов.
- Эффективная версия кэша: `photo:<photo_version>`, для первого фото без поля — постоянная условная `legacy`. При отсутствии поля сохраняется последняя известная эффективная версия, в том числе после перезапуска. Изменение версии меняет параметр `v` URL JPG. Условная и серверная версии имеют разные пространства имён.
- Кэш байтов обслуживается существующим CachedNetworkImage на нативных платформах и браузером на Web. Реестр не гарантирует бессрочное хранение байтов: после очистки/вытеснения кэша фото может загружаться повторно. Меню/цены не берутся из фото-кэша; публичные фото загружаются без токена.
- Зависимость выпуска: фактическая замена фото по серверному сигналу требует отдельной доработки/загрузки выгрузки Zak и проверки пользователем. Старый JSON поддерживается до этого.

## Критерии завершения

Смена версии при прежнем имени меняет URL; повторная загрузка/перезапуск сохраняет URL при той же или отсутствующей версии; источники изолированы; старый JSON работает; конфликт версий не повреждает реестр. Общий код применим к трём платформам; сборка и приёмка учитываются отдельно.

## Что сделано

- [menu_models.dart](../../lib/features/menu/menu_models.dart): `photoVersion` хранит исходный сигнал, `imageVersion` — разрешённую версию кэша. Поля остальных моделей сохранены при восстановлении версий.
- [menu_photo_versions.dart](../../lib/features/menu/menu_photo_versions.dart): SharedPreferences-реестр с изоляцией по источнику, сохранением последней версии, постоянной условной версией, проверкой конфликтов и очередью записи. Повреждённый JSON реестра восстанавливается без использования цен/меню из хранилища.
- [menu_repository.dart](../../lib/features/menu/menu_repository.dart): после парсинга восстанавливает эффективные версии; Controller и UI не обращаются к хранилищу напрямую.
- [menu_image.dart](../../lib/features/menu/menu_image.dart), [menu_page.dart](../../lib/features/menu/menu_page.dart): передача версии в URL и ключ компонента изображения. При новой версии компонент заменяется и запрашивает другой URL.
- Семь новых тестов и дополнение существующей widget-регрессии. Контроллерные тесты получили mock SharedPreferences для новой зависимости.
- Исходники и локальный Web повышены до 0.1.0+5; источник меню/фото прежний, рабочий `obedmoscow.ru/data/`. Сборка включает ранее принятые FL-06-20c…20f.
- Web: общий код, тесты и release-сборка; браузерная приёмка и SSH-публикация не выполнялись. Android: общий код проверен локальными тестами; APK/AAB не пересобраны, установка не проверялась. iOS: общий код изменён согласованно; сборка и runtime не запускались по запрету пользователя.
- Zak и старый сайт не менялись. Накопленные исходные пользовательские изменения сохранены; коммит не выполнялся.
