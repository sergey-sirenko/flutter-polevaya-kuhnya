# FL-06-20l — Согласие при регистрации и тексты политики (W08)

## Назначение

- Бизнес-цель: пользователь читает политику и отдельное согласие до отправки регистрационных данных, явно разрешает обработку.
- Требования ТЗ: NFR-SEC-6; W08 в [аудите](../web-completeness-audit.md).
- Модуль: регистрация, информационные страницы; общий Flutter-код Android/iOS/Web.
- Ответственный: LLM; живую Web-проверку выполняет владелец.

## Входные условия

- Пользователь 28.09.2026 поручил по W08 «сам придумай»: тексты и клиентское поведение выбираются в этой задаче, дополнительное согласование текста не требуется.
- W07 относится к версии приложения, W10 — к версии фотографии. Владелец подтвердил публикацию `photo_version` после своей ручной доработки Zak. Анонимное чтение рабочего меню подтвердило 614 непустых строковых значений; исходники Zak и обновление фото в браузере не проверялись.
- Существующие реквизиты оператора берутся из SiteContent. API регистрации context_v1 не меняется; доказательство получения согласия на сервере и FR-A6 не реализуются этой клиентской подзадачей.
- iOS не тестировать; мобильные сборки отложены. Реальные письма/регистрации/заказы не выполнять. SSH-выкладка — отдельный шаг.

## Оценка перед выполнением

- Оцениваемый объём: вся клиентская подзадача.
- Сложность: 3/10.
- Трудоёмкость: низкая; ≈2% суммарных трудозатрат этапа 6.
- Рекомендуемая категория LLM: средняя.
- Основание: тексты, навигация с сохранением формы, защита первого запроса и повторной попытки, проверки общего кода. Живой Web — внешнее ожидание.

## Контракт и решение

- До registrationstatus и registrationstart требуется отдельная изначально пустая галочка согласия. Без неё сетевых запросов нет, пользователю показывается причина.
- Политика и самостоятельный текст согласия открываются поверх маршрута регистрации; возврат сохраняет введённые данные и сделанный выбор.
- Согласие относится только к текущему процессу регистрации: отмена, истечение/сброс и уход с формы требуют нового выбора. Не сохранять согласие как бессрочное разрешение в SharedPreferences.
- API и payload прежние. Клиентская галочка не является реализованным серверным журналом доказательств согласия; это отдельная зависимость полного NFR-SEC-6.
- Политика описывает известные цели, данные, способы связи и отзыв; обещание немедленного автоматического удаления аккаунта снято. Сроки не подменяются выдуманным фиксированным числом дней.

## Критерии завершения

Без согласия данные не уходят в регистрацию; документы доступны и возврат сохраняет форму; после сброса согласие требуется заново. В текстах нет обещания реализованного удаления аккаунта. Общий код работает с прежним API. Публикация и браузерная приёмка учитываются отдельно.

- В форме отдельная незаполненная галочка до registrationstatus/registrationstart и ссылки на оба документа. Снятие галочки перед start тоже запрещает запрос.
- Открытие документов через push/pop сохраняет поля и выбор; кнопка возврата показана у документа, открытого поверх регистрации. Прямые адреса доступны гостю. При императивном push go_router сохраняет адрес формы в Web по своему штатному поведению; прямые адреса документов работают отдельно. Пароль не переносится в URL или хранилище.

- Payload API прежний. Галочка не передаётся серверу и не сохраняется постоянно; журнал факта/версии согласия остаётся отдельной серверной зависимостью. Клиентская W08 реализована, весь NFR-SEC-6 не объявляется завершённым.
- Android/iOS/Web используют общий код. Android не пересобирался и не запускался; iOS не собиралась/не тестировалась. Web +8 собран локально; test остаётся +7. Zak и старый сайт этой задачей не изменялись.
- Правовая основа отдельного согласия/отзыва: [152-ФЗ, статья 9](https://www.consultant.ru/document/cons_doc_LAW_61801/6c94959bc017ac80140621762d2ac59f6006b08c/), сверена 28.09.2026. Реализация не объявляется подтверждением полного юридического соответствия и серверного учёта согласия.
