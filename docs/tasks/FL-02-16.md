# FL-02-16 — Определить безопасный повтор заказа

## Назначение

- Бизнес-цель: после потери ответа выяснять результат отправки корзины и исключать непредусмотренную повторную запись заказа.
- Требования ТЗ: FR-C3, FR-C5, API-3; [этап 2 дорожной карты](<../../Дорожная карта.md>), [архитектура](../../ARCHITECTURE.md).
- Модуль: Zak HTTP `Orders/basket`, запись `ЗаказПокупателя`; будущая отправка Flutter — FL-05-09/10/12/17.
- Ответственный: агент; загрузка и приёмка изменений Zak — владелец ИБ.

## Критерии завершения

Протокол различает подтверждённый успех, подтверждённый отказ и неизвестный исход. Для нового клиента повтор с тем же `submissionId` возвращает постоянную квитанцию, новая попытка проверяет версии дней, а ошибка многодневной записи откатывает все дни. Проверяемые границы и недостающие условия явно записаны; старый HTTP/SOAP сохраняет прежнюю форму. Гарантии должны быть подтверждены на платформе до клиентского выпуска.

## Что сделано

- Сверены точка остановки, правила проектов, оценка и Git. Пользователь заранее предупреждён о возможной правке Zak.
- Исходный `Orders/basket` пишет дни по очереди без общей транзакции; новый документ может быть создан до позднего отказа. `order[]` из истории не показывает пустые дни и не доказывает, что конкретная попытка была принята. Старый сайт посылает JSON без ID, SOAP Mob использует другой обмен.
- [Контракт Zak v1.0](../../../Zak/docs/safe-order-retry.md) закрепляет неизменный `submissionId` всей корзины, предварительное чтение `revision` дней, атомарную запись и постоянную квитанцию. `not_found` в статусе не означает безопасного нового ID; повторяется только тот же ID и снимок.
- По прямому ответу пользователя создан [регистр](../../../Zak/Konf/InformationRegisters/ПовторыОтправкиЗаказов.xml) и запись в `Konf/Configuration.xml`. В [ОбменHTTP](../../../Zak/Konf/CommonModules/ОбменHTTP/Ext/Module.bsl) новый режим сериализует отправки пользователя, проверяет версии, откатывает отказ любого дня и сохраняет SHA-256 состава и квитанцию в одной транзакции. [Диспетчер](../../../Zak/Konf/HTTPServices/Obmen/Ext/Module.bsl) направляет `basketstate`/`basketresult`. Запрос без `submissionId` сохраняет прежнюю ветку; отказ `ЗаписатьЗаказ`, отличный от `Истина`, больше не считается успехом.
- Пользователь отдельно подтвердил загрузку FL-02-14 и FL-02-15 в ИБ. Их состав/версия и живая работа не проверены; подготовленная здесь FL-02-16 требует отдельной загрузки.
