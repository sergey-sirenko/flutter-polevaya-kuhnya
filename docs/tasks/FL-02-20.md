# FL-02-20 — Отзывать токен при выходе

## Назначение

- Бизнес-цель: завершать текущую серверную сессию при выходе Flutter, сохраняя локальный выход при любом сетевом исходе.
- Требования: FR-A5, API-6 [Ж], §5.2 дорожной карты; NFR-SEC-4.
- Модуль: Zak HTTP `User/logout`, Flutter `SessionRepository`/`SessionController`.
- Ответственный: агент — исходники и локальная проверка; владелец ИБ — загрузка и живая приёмка.

## Входные условия

- Зависимые: FL-01-13 (локальная сессия), FL-02-14 (регистр сеансов и привязка устройства), FL-02-17 (ошибки/CORS), FL-02-19 (совместимость).
- Окружение: Zak — выгрузка Конфигуратора, совместимость 8.3.12; Flutter `master`. Пользователь подтвердил загрузку предшествующих серверных изменений, но SHA ИБ не установлен.
- Ограничения: не запускать 1С, не обновлять ИБ, не отзывать живой тестовый токен до загрузки; не публиковать клиентов. Изменения только BSL и Dart, без метаданных. Старый сайт/Mob не меняются.
- Предупреждение пользователю до правки: Zak `ОбменHTTP` и диспетчер `HTTPServices/Obmen`, точечный отзыв записи `СеансыПользователей`; без изменений XML, заказов и привязки устройства.

## Контракт и обратная совместимость до реализации

- `POST /Zakaz_http/hs/Obmen/V1/User/logout`, JSON `{token,deviceId}`. Пароль не передаётся.
- Действующий токен и соответствующее устройство позволяют записать пустой последний токен только для текущего ключа `Пользователь/Сотрудник/ИдКлиента` в периодическом регистре. Привязка устройства, профиль, другие сеансы и заказы сохраняются. Для старого токена без серверного `ИдКлиента` достаточно действующего токена; отправленный `deviceId` синтаксически проверяется.
- Успех: HTTP 200, `{success:true,code:"signed_out"}`. Недействительный/уже отозванный токен: 401 `invalid_session`; несовпадение устройства: 403 `device_mismatch`; неверный JSON: 400 `invalid_request`; сбой записи: 500 `server_error`. Ошибка содержит `error` для старых клиентов. CORS через общий диспетчер, `Cache-Control: no-store`.
- Flutter сначала исключает прежнее поколение сессии и удаляет локальный токен. Серверный POST выполняется best effort и не удерживает локальный выход; его отказ не восстанавливает сессию. `deviceId` сохраняется. Старый сайт/Mob не вызывают маршрут и продолжают прежний локальный выход.
- Выпуск: Zak с новым маршрутом загружается до клиента, который его вызывает. До загрузки старый сервер вернёт отказ, но локальный выход Flutter завершится.

## Критерии завершения
