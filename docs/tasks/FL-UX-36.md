## Что установлено
- `_OrderPreparationPageState._prepare()` в `lib/app/router.dart` вызывает `CartEditController.begin(widget.dateKey)`.
- `begin()` в `lib/features/cart/cart_edit_controller.dart` при неактивном наборе и `state.hasSavedWork` выставляет сообщение со снимка и возвращает false до сетевой `_prepare()`.
- `hasSavedWork` означает recovery != null, recoveryError либо restoring. `begin()` предварительно ожидает ready, поэтому наличие снимка или ошибка его чтения — значимые причины; точный вариант у пользователя без чтения состояния не установлен.
- Снимок загружается через CartWorkStore для текущих login/device при создании контроллера. Сохранность набора предназначена для защиты локальных правок.
- Экран подготовки любой false превращает в общий экран ошибки с «Повторить загрузку». Обработчик лишь сбрасывает локальные loading/error и повторно вызывает тот же `_prepare()`/`begin()`; он не вызывает resume/discard/retryRead. При неизменном hasSavedWork результат снова тот же. Это несоответствие действия причине блокировки, а не доказанная ошибка сети или 1С.
- В заказах CartWorkBanner предоставляет отдельные resume и discard с подтверждением. Доступный обход: «Вернуться в заказы» и выбрать «Продолжить набор» либо «Начать заново»; успешное восстановление на текущих данных не проверено. Сброс удаляет локальные правки, серверные заказы сохраняются.

## Исправление по поручению «сделай»
Оценка оставшейся реализации: сложность 3/10, трудоёмкость низкая, LLM средняя; объём соответствует предыдущему предложению.

В router.dart состояние сохранённого/заблокированного обычного набора показывает CartWorkBanner вместо общего «Повторить загрузку»: красные действия в одной строке, восстановление через resume, повтор чтения при recoveryError, сброс через существующий диалог. После продолжения открывается фактический день восстановленного набора; после успешного подтверждённого сброса запускается подготовка даты исходного запроса. Ошибки восстановления/сброса выводятся из состояния контроллера. Для обычной ошибки подготовки прежний retry сохранён.

В CartWorkBanner добавлен необязательный onDiscarded, вызываемый только после успешного сброса (нет active/hasSavedWork/blocked/message). Прежние места использования не меняют поведение. Переход после восстановления и новая подготовка после сброса проверяют актуальность маршрута, чтобы не возвращать пользователя с другого экрана. Проверки состояния заказов, защита локального набора и серверные операции не менялись.

pubspec.yaml и оба build-поля web/version.json: 1.0.0+76. Минимум policy и null Android/iOS сохранены; сборка включает FL-UX-33…35. Общий UI Web/Android/iOS; Android/iOS runtime не проверяется, новые мобильные сборки не выполняются. API/Zak и пользовательские данные не изменены.
