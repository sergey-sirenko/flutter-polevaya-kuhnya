# FL-07-03 — Зафиксировать идентификаторы

## Назначение и входные условия

- Цель: согласовать постоянные Android Application ID и iOS bundle ID до подписей и создания карточек магазинов.
- Требования: [дорожная карта, этап 7](../../Дорожная%20карта.md), [ТЗ §10](../../Техническое%20задание.md), [архитектура C-06](../../ARCHITECTURE.md), [FL-07-02](FL-07-02.md).
- Заказчик ранее установил название «Полевая кухня» / `Polevaya kuhnya`; отображаемое название не является техническим ID.
- Заказчик подтвердил, что карточки приложений ещё не созданы. Кабинеты не открывались.
- Ограничения: не создавать карточки, подписи и не запускать iOS-тестирование. Zak не затрагивается.

## Оценка перед выполнением

- Вся подзадача: сложность 5/10; трудоёмкость средняя, ≈5% этапа 7; LLM — средняя.
- Основание: значение должно быть допустимым для обеих платформ и устойчивым для обновлений; цена ошибки после первой загрузки велика. Проверка доступности в кабинетах зависит от доступа заказчика и учитывается отдельно.

## Фактические исходники и предложение

| Место | Текущее временное значение | Предлагаемое постоянное значение |
|---|---|---|
| `android/app/build.gradle.kts`: `applicationId`, `namespace` | `com.example.polevaya_kuhnya` | `ru.obedmoscow.polevayakuhnya` |
| `android/app/src/main/kotlin/.../MainActivity.kt`: пакет | `com.example.polevaya_kuhnya` | `ru.obedmoscow.polevayakuhnya` |
| `ios/Runner.xcodeproj/project.pbxproj`: Runner `PRODUCT_BUNDLE_IDENTIFIER` | `com.example.polevayaKuhnya` | `ru.obedmoscow.polevayakuhnya` |
| Там же: RunnerTests | `com.example.polevayaKuhnya.RunnerTests` | `ru.obedmoscow.polevayakuhnya.RunnerTests` |

**Решение заказчика от 28.09.2026:** домен `obedmoscow.ru` находится под его управлением, карточек приложений ещё нет; значение `ru.obedmoscow.polevayakuhnya` согласовано для Android Application ID и iOS bundle ID. Одинаковая строка удобна для учёта, но магазины проверяют уникальность каждый в своём контуре. Она не определяет ключи подписи и не доказывает совместимость обновлений между магазинами. Доступность конкретного ID в кабинетах не проверялась.

По [Android Developers](https://developer.android.com/build/configure-app-module) Application ID отличает приложение на устройстве и в Google Play, после публикации его не следует менять; при обновлении нужны тот же ID и подпись. [Google Play](https://support.google.com/googleplay/android-developer/answer/9859152?hl=en) считает имена пакетов уникальными и постоянными. [Apple](https://developer.apple.com/documentation/BundleResources/Information-Property-List/CFBundleIdentifier) не позволяет сменить bundle ID после загрузки сборки, а [регистрация App ID](https://developer.apple.com/help/account/identifiers/register-an-app-id) требует совпадения с проектом Xcode. Источники проверены 28.09.2026.
