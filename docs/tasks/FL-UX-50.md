# FL-UX-50 — Действия при конфликте сохранённого набора

## Назначение
Устранить повторяющееся предложение «Продолжить набор» после подтверждённого конфликта исходной версии/состава. По сообщению пользователя 11.10.2026 повторный клик возвращает тот же результат. Модуль: общая корзина Web/Android/iOS; ответственный Codex.

## Входные условия
Исходная локальная сборка +89. Не сливать конфликтующие данные и не удалять локальные правки без подтверждения. Сетевой сбой допускает повтор загрузки. API snapshot v1 и серверные заказы не меняются; FL-UX-48/49 сохранить.

## Оценка перед выполнением
Вся задача: сложность 2/10; трудоёмкость низкая; LLM средняя. Отдельная задача без определённой доли этапа. Основание: различение подтверждённого конфликта и временной ошибки, действия и автоматическое восстановление UI.

## План и критерии завершения
- Явный флаг конфликта в состоянии без разбора текста ошибки.
- При конфликте убрать «Продолжить набор», сохранить пояснение и «Начать заново» с подтверждением.
- Сохранить возможность повтора временной ошибки.
- Целевые тесты, analyze/version/diff и тестовый Web +90; обновить PROJECT_STATE.

## Состояние
Начата 11.10.2026. Проверки и реализация выполняются, публикация не поручена.

После локальной реализации — пользовательская SSH-выкладка и проверка сообщения/подтверждения. Мобильный runtime не запускать, серверные данные не менять.

## Результат 11.10.2026
Реализация завершена. CartEditState.recoveryConflict выставляется при подтверждённом несовпадении исходной revision или состава доступного заказа. CartWorkBanner скрывает «Продолжить набор» и автоматический повтор при этом флаге, сохраняя сообщение и «Начать заново» с прежним подтверждением. CartPage также не запускает автоматическое восстановление уже известного конфликта. Сообщение явно объясняет, что прежний набор продолжить нельзя и для загрузки актуального заказа необходимо подтвердить сброс локальных правок. Флаг не определяется по строке ошибки.

Временная ошибка сети не считается конфликтом: кнопка повторного продолжения остаётся, а успешное восстановление сохраняет локальные количества. Сброс не происходит автоматически. «Назад» в подтверждении сохраняет снимок; подтверждение очищает снимок и флаг. API/1С и режим повтора не менялись. Фактические версии/состав аккаунта на снимке не запрашивались: исправлено действие интерфейса после уже обнаруженного расхождения, причина конкретного изменения на сервере не установлена.
