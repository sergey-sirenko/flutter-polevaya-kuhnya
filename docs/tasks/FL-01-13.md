## Критерии завершения

Repository получает общий транспорт через Riverpod. Наличие сохранённого токена само по себе не даёт доступ: сессия подтверждается серверным ответом. HTTP 401 очищает сессию; потеря связи закрывает личные данные без ложного признания токена истёкшим. Выход и смена пользователя исключают возврат старых ответов. Пароль и профили не записываются в хранилище, секреты не журналируются.

## Что сделано

27.09.2026 пользователь ответил **«Подтверждаю эту модель»**: Flutter использует постоянный UUID без `New3_`, восстановление через `User/login` с `token`/`deviceId`; неоднозначный HTTP 400 при проверке сессии закрывает личные экраны без удаления токена. Проверка привязки сервером остаётся в FL-02-11/17. Это принятие клиентской модели; готовность серверных проверок не заявляется.

[SessionStorage](../../lib/core/auth/session_storage.dart) хранит токен и UUID v4 через `flutter_secure_storage`, отдельно для окружения и API-базы. Пароль, профиль и история не сохраняются. Выход удаляет только токен, UUID сохраняется. Операции хранилища упорядочены, чтобы поздняя запись не отменила удаление. Миграция старого `DEVICE_ID` не выполняется (FL-08-04). Ошибки хранилища не содержат секреты в диагностике.

[SessionRepository](../../lib/core/auth/session_repository.dart) использует [общий ApiClient provider](../../lib/core/api/api_client_provider.dart). Восстановление отправляет только `token` и `deviceId`, требует успешный ответ с объектом `user`, сохраняет прежний токен, если сервер не выдал новый. Полная схема условий/истории профиля остаётся FL-02-11; профиль не попадает в состояние сессии или хранилище.

[SessionController](../../lib/core/auth/session_controller.dart) вручную объявлен через NotifierProvider. Различает восстановление, гостя, подтверждённую сессию и недоступность проверки. При каждой смене сессии меняется поколение запросов; поздние ответы проверки/входа не восстанавливают прежнего пользователя. Будущий auth Controller передаёт вызов своего Repository в `signIn`, поэтому поколение фиксируется **до** запроса входа. HTTP 401 удаляет токен; сеть, HTTP 400 и неверный ответ при восстановлении закрывают доступ, сохраняя токен. Ошибка записи не считается успешным входом, ошибка удаления — успешным выходом.

[SessionApi](../../lib/core/auth/session_api.dart) — адаптер для защищённых Repository, привязанный к одному поколению сессии. Он нужен, чтобы добавлять токен только к API и отвергать устаревшие ответы без обратной зависимости общего ApiClient от Controller. Личный Repository/его состояние должны зависеть от `sessionApiProvider`, чтобы при смене пользователя сбрасывать данные. Текущих бизнес-репозиториев ещё нет; их очистка проверяется вместе с реализацией соответствующих модулей. Публичные данные используют `apiClientProvider` без сессионных полей.

`sessionStatusProvider` теперь отражает реальную сессию, существующий router обновляется без пересоздания. В экране недоступной сессии добавлен явный повтор проверки. При logout личный маршрут переходит ко входу с сохранённым `from`. В ApiClient отключены автоматические HTTP-перенаправления: POST с токеном не должен уходить на адрес из `Location`. В установленном `http` 1.6.0 BrowserClient использует для этого `redirect: error`; платформенная приёмка остаётся впереди.
