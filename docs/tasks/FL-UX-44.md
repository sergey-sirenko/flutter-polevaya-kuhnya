# FL-UX-44 — Категории после полной сохранённой отмены дня

## Назначение
По сообщению пользователя после полной отмены ранее сделанного заказа значок корзины пустого дня должен снова открывать категории на адаптивном экране.

## Входные условия и оценка
В +83 skipCart требует revision=none; календарь считает днём без заказа любой день с пустым dishes. Существующая версия отменённого пустого заказа не должна определять переход. Фактический ответ API пользователя не запрашивался. Вся подзадача: сложность 2/10, трудоёмкость низкая, LLM лёгкая; уточнение условия по уже подготовленному составу. Отдельный UX-пакет вне этапа. Тесты/превью не запускать по сохранённому ограничению, мобильные сборки не пересобирать.

## План и критерии
- При ширине <1200 и пустом исходном составе выбранного дня плюс отсутствии локальных блюд открыть категории независимо от версии заказа.
- При непустом исходном составе и локальной очистке оставить корзину для сохранения отмены.
- Сохранить проверки доступности, серверные версии, другие дни, широкий экран и Назад.
- Поднять номер, format/analyze/diff-check/version-policy/Web-сборка, обновить состояние.

Начата 09.10.2026; локальная реализация завершена; статические проверки и Web-сборка +84 успешны; публикации нет.

## Что сделано
В router.dart skipCart после успешной подготовки выбранного дня сравнивает originals[dateKey]?.isEmpty==true вместо preparedRevisions[dateKey]=='none'; отсутствие локального dayFor и ширина <1200 остаются обязательными. Непустой исходный состав при локальном удалении не пропускает корзину: пользователь должен сохранить отмену. Отменённый на сервере пустой день открывает категории независимо от сохраняющейся версии. Неизвестный исходный состав (null) не считается пустым.

Версии заказа продолжают использоваться для контроля конфликтов и отправки без изменений. Код сохраняет Назад из категорий в заказы, другие дни, проверки доступности и актуальности маршрута. Фактический серверный ответ после отмены пользователя не читался; новая ветвь следует подтверждённому исходному составу подготовленного снимка.

pubspec.yaml и оба build-поля web/version.json — 1.0.0+84, минимум policy и null Android/iOS сохранены. Общий код Web/Android/iOS; мобильные сборки/runtime не выполнялись, API/Zak/пользовательские данные не изменялись. Тесты/превью/живой цикл заказа не запускались по ограничению. Commit/push/публикации нет.
