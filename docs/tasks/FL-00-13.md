## Что сделано

### Маршруты

`js/router.js` использует hash-routing и переводит неизвестный маршрут на `#home`. Информационные маршруты: `#home`, `#about`, `#contacts`, `#how-to-order`, `#delivery`, `#terms`, `#not-offer`. Заказные и профильные: `#order`, `#profile`. Мобильные PWA-маршруты: `#pwa/menu`, `#pwa/categories`, `#pwa/day-selection`, `#pwa/cart`, `#pwa/profile`. Платёжные страницы: `#payment/success`, `#payment/failure`. Query-параметры используются для перехода к категории/дню; маршруты обслуживаются одной SPA-оболочкой.

### Service Worker и кэш

Каноническая версия — `439`, короткое имя `v439`, Cache Storage `polewaya-cache-v439`, версия Worker `v1.339`; значения дублируются в `js/config/cache-version.js` и `js/config/sw-cache-version.js`. `service-worker.js` предварительно кэширует оболочку, CSS/JS, manifest, иконки, placeholder и offline-страницу. Для ресурсов используется query `?v=439`.

Навигация и JavaScript работают по network-first с fallback в кэш/offline; обычные same-origin GET — cache-first с последующим кэшированием; `/data/pictures/` кэшируется отдельно с учётом URL; `/api/`, внешний `hleb-sol.su`, `/data/*` кроме картинок, non-GET и Range-запросы обходят Worker. В `activate` удаляются кэши с другим именем и выполняется `clients.claim()`, при установке — `skipWaiting()`.

`index.html` содержит inline cache-heal: при расхождении ожидаемого кэша удаляет Cache Storage и регистрации Worker один раз за сессию по ключу `sessionStorage` и перезагружает страницу. `js/cache-manager.js` также умеет очистить кэши/регистрации и Web Storage; это административный механизм, а не серверная синхронизация. Обновление уже установленного PWA и отсутствие reload-loop браузером не проверялись.

### Локальные ключи и состояние

Канонические ключи `localStorage` из `js/config.js`: `foodCart`, `authToken`, `userData`, `currentView`, `allowedOrderDays`, `currentMenuWeek`, `currentMenuDay`, `currentCartWeek`, `currentCartDay`, `cartActivated`. Дополнительно исходники используют `DEVICE_ID`, `image_versions`, `image_meta_<path>`, а для UI cache-heal — session-флаг; логин/пароль сессии (`auth_login_session`, `auth_password_session`) и `pwaInstallHintDismissed` находятся в `sessionStorage`.

`foodCart` хранит корзину по датам и блюдам; `authToken`/`userData` сохраняют авторизацию; `DEVICE_ID` переживает logout. Очистка cache-manager удаляет Web Storage целиком, тогда как обычный logout удаляет только auth/profile/session и сбрасывает корзину/индикаторы согласно коду.

### Установка и загрузки

`manifest.json` задаёт standalone PWA с `start_url: /`, `scope: /`, portrait-primary и иконками 72–512 px, включая maskable/monochrome. `pwa-install.js` использует `beforeinstallprompt`/`appinstalled` на поддерживаемых Chromium, подсказку Add to Home Screen для iOS и session-флаг отказа. Установка зависит от браузера; факт установки не проверялся.

`download-menu.js` проверяет `data/download/1.xls` и `2.xls` через GET с Range, раз в 30 секунд обновляет доступность и создаёт скачивание. В checkout эти XLS присутствуют. APK в `data/download` отсутствует; README и технический контекст описывают APK как эксплуатационный/игнорируемый runtime-артефакт, поэтому его наличие, версия, подпись и публикация не подтверждены.

### Публикация и границы миграции

Документы выпуска требуют чистый проверенный SHA ветки `test`, отдельный test-deploy, приёмку, затем fast-forward `main` и production-deploy; `data/`, базы, APK и письма исключены из обычного выпуска. Test подключает runtime-меню/картинки ссылками на production, а текущий Caddy test-vhost и новый Flutter-vhost ведутся отдельно. В рамках FL-00-13 публикация, коммиты, push, FTP, APK и серверные изменения не выполнялись.
