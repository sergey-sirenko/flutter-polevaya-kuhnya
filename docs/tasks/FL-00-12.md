## Что сделано

### Серверный источник истины

В `ОбменДанными.ЗаписатьЗаказ` Zak повторно получает меню и для каждой строки устанавливает актуальную `ЦенаРеализации`; присланные клиентом цена и итог не принимаются как источник истины. Рассчитываются `Сумма` строки, `ИтогПоКолонкеСумма`, `СуммаДоставки`, процентная скидка и скидка клиенту, затем записывается документ `ЗаказПокупателя`.

Доставка выбирается по таблице интервалов контрагента (`ИнтервалС`, `ИнтервалПо`, `Сумма`); при подходящем бесплатном интервале возвращается ноль. Процентная скидка берётся из настроек пользователя. Для обычного пользователя `СкидкаКлиенту` применяется как сумма дня; для новой формы скидка сотрудника переносится в `БезОплатыДень` строк заказа, а `СкидкаКлиенту`/`СкидкаКлиентуСумма` обрабатываются отдельно.

### Ограничения суммы

Минимальная сумма заказа выбирается из сотрудника, если задана, иначе из пользователя. `НедостаточнаяСуммаЗаказа` сравнивает сумму после скидок с минимумом и формирует отказ. Ограничение суммы выбирается аналогично и проверяется за день, неделю или месяц; при недоступном периоде используется день. Для периодов учитываются ранее проведённые непомеченные заказы, а для сотрудника — строки текущего сотрудника. Точные места вызова проверок в полном цикле записи и фактические сообщения требуют runtime-сверки.

В ответе login сервер передаёт `Limit`, `LimitPeriod`, `MinimumOrderAmount`, `MinimumPaymentAmount`, `DiscountPercentage`, `DiscountClient`, `DiscountPromotion` и варианты полей скидки. Эти значения описывают правила пользователя, но не являются подтверждением конкретной суммы текущей корзины.

### Клиентское отображение

Сайт рассчитывает предварительные итоги для интерфейса: цена × количество, процентная скидка, `DiscountClient`, `MinimumPaymentAmount`, итоги дня и недели. Округление выполняется JS через `Math.round`; при дотации учитывается минимальная оплата сотрудника. В `Orders/basket` передаётся только количество и рассчитанный `DiscountClient` по строке, а сервер пересчитывает цену, доставку и итог. После успеха клиент использует возвращённый `order`/профиль.

Таким образом, отображаемая до отправки сумма может измениться из-за актуальной цены, серверных интервалов доставки, скидок, лимитов, доступности дня или параллельного изменения заказа. Финальным считается значение из ответа/истории Zak, а не локальный расчёт.

### SOAP/Mob

WSDL содержит `ЦенаРеализации`, `Сумма`, `СкидкаПроцент`, `СкидкаПроцентСумма`, `СкидкаКлиенту`, `СкидкаКлиентуСумма`, `СуммаДоставки`, `ИтогПоКолонкеСумма`, `ОграничениеПоСумме`, `МинимальнаяСуммаЗаказа`, `МинимальнаяСуммаОплаты` и поля оплаты. Mob передаёт/получает эти значения в `ОбменЗаказами`; локальный обмен также пересчитывает строки по текущему меню. Конкретное согласование округления HTTP и SOAP статически не доказано.

### Черновой вывод, не утверждённый контракт

Сервер Zak является окончательным источником сумм. Flutter должен показывать предварительный расчёт с явным обновлением после ответа сервера и не фиксировать локальную цену как итог. Для утверждения контракта нужны обезличенный ответ `Orders/basket`, профиль с параметрами скидок/лимитов и сценарии минимум для обычного пользователя, сотрудника, доставки, скидки и отказа по минимуму/лимиту.
