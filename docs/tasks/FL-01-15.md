## Критерии завершения

Workflow описывает последовательные `flutter analyze` и `flutter test` для изменений, без секретов и сборок. Ошибка каждого шага останавливает job. Локально проверены синтаксис и те же команды; удалённый запуск обозначен отдельно.

## Что сделано

[`.github/workflows/flutter-ci.yml`](../../.github/workflows/flutter-ci.yml) запускается на push, pull request и вручную. Один Linux job использует Flutter 3.47.1 и последовательные `flutter pub get --enforce-lockfile`, `flutter analyze --no-pub`, `flutter test --no-pub -r compact`. Шаги без `continue-on-error`: штатная семантика GitHub Actions прекращает job при ненулевом коде. Доступ token ограничен `contents: read`, checkout не сохраняет credentials. Секреты, сеть 1С, сборки и публикация не добавлены.

[Документ CI](../ci.md) описывает локальное воспроизведение и границу проверки. Версии checkout и flutter-action сверены с репозиториями действий; Flutter 3.47.1 — текущий локальный SDK и версия в changelog Flutter. В Git Flutter коммитов и remote нет, поэтому реальный runner ещё не запускался.
