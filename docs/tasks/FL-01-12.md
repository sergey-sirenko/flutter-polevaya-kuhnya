## Критерии завершения

Один `ApiClient` принимает внедрённый HTTP-клиент, отправляет JSON POST в API и читает публичный JSON с отдельной базы. Ошибки таймаута, сети, отказа доступа, бизнес-отказа, HTTP-сбоя и неверного формата различимы. HTTP 401 обозначает недействительную сессию; неоднозначный HTTP 400 сам по себе её не очищает. Запись не повторяется автоматически, потеря ответа помечает неизвестный исход. Секреты не журналируются. Локальные тесты проходят без сетевых вызовов к рабочим адресам.

## Что сделано

Сверены фактические границы конфигурации и наблюдаемые формы ответов. [ApiClient](../../lib/core/api/api_client.dart) принимает `AppConfig` и внедряемый `http.Client`, отправляет один JSON POST на вызов в API-базу и отдельно читает публичный JSON из базы данных. Относительный путь проверяется до сетевого вызова: абсолютный URL, выход из базы, query и fragment не допускаются. Токен, `deviceId` и иные поля авторизации автоматически не добавляются; конкретный Repository должен передать их явно согласно контракту операции. Тело запроса и ответ не журналируются.

[ApiException](../../lib/core/api/api_exception.dart) различает сеть, таймаут, HTTP 401, HTTP 403, бизнес-отказ, прочий HTTP-сбой и неверный формат. В старом `{success:false,error}` и новом `{success:false,code,message,error}` сохраняются машинный код и доступное сообщение. HTTP 200 с `success:false` остаётся отказом. Для POST таймаут/потеря связи помечаются `outcomeUnknown`; клиент не повторяет запрос. Это консервативно и для читающих POST 1С. Общий HTTP 400 для неверного токена, реквизитов и бизнес-отказа нельзя автоматически считать истечением сессии; точная семантика остаётся за FL-02-17. `ApiException.toString()` не выводит текст и код ответа, чтобы случайное журналирование исключения не раскрыло их.
