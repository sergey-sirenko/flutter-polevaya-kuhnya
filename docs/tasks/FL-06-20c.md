# FL-06-20c — Результат и восстановление попытки заказа

## Назначение

- Бизнес-цель: исправить W01/W02 [аудита](../web-completeness-audit.md), завершить безопасный клиентский сценарий заказа.
- Требования: FR-C3/C4/C5, BL-2, ADR-1/3/6.
- Модуль: общий cart, строки, синтетические тесты; сервер не меняется.
- Ответственный: LLM; ручная приёмка Web пользователем отдельно.

## Входные условия

- Зависимости: FL-06-20b, существующие basketstate/basket/basketresult, [API](../api-1c.md) и [канонический retry-контракт](../../../Zak/docs/safe-order-retry.md).
- Контракт без изменений: сначала revision; POST с неизменными submissionId/телом; при неизвестном исходе чтение результата, повтор только того же снимка при not_found. Никакой автоматической записи при запуске.
- Ожидаемый результат: успех виден при пустой корзине; попытка восстанавливается по API/владельцу; поздний ответ не влияет на другую сессию; новые правки черновика сохраняются.
- Ограничения: только локальные тесты без реальных реквизитов/писем/заказов, 1С не менять. Сборки/публикация пропущены, iOS и мобильная приёмка отложены.

## Что сделано

Добавлен [CartSubmissionStore](../../lib/features/cart/cart_submission_store.dart): формат v1, владелец, область API/окружения, неизменный JSON-снимок без токена/пароля, проверка восстановленных данных и последовательные записи. CartRepository делегирует ему хранение; новый файл решает конкретную задачу постоянной операции.

[Контроллер](../../lib/features/cart/cart_submit_controller.dart) восстанавливает запись до разрешения новой операции; старый ключ/повреждение блокируют новую отправку, без удаления данных. Старт не вызывает сеть. Проверка результата сначала читает basketresult; только not_found разрешает повтор прежнего ID/тела. accepted должен содержать совпавшую квитанцию. HTTP 5xx, повреждённый ответ и отсутствие квитанции сохраняют неизвестный исход; отказ чтения статуса не разрешает запись. Поздние ответы сверяются с текущим repository/поколением. Revision каждого дня должен быть получен, неподтверждённый none не подставляется.

Успех очищает совпавшие позиции снимка, сохраняет изменённые/новые позиции. Запись очищенного черновика предшествует удалению попытки. Возврат false хранилищем проверяется; при сбое локального завершения известного успеха сообщение прямо говорит, что сервер принял заказ, но новый заказ заблокирован до проверки результата. Очередь хранения фиксирует владельца/снимок в момент изменения и не загружает прежнего владельца в новый сеанс; обновление полей того же профиля не очищает корзину.

CartPage показывает успех/серверные суммы независимо от пустоты корзины, предлагает «К заказам» и «Продолжить выбор». История обновляется при явном переходе «К заказам», а не скрывающим успех restore сразу после ответа. Во время восстановления/отправки/неизвестного исхода/ошибки восстановления UI блокирует количества в меню и корзине, очистку и повтор из истории. Сообщения добавлены в AppStrings.

## Препятствия

Живая приёмка API и числовая сверка остаются открытыми. Старый cart.pending не содержит области API; автоматически повторять его нельзя. При наличии такого ключа требуется разбор исхода/источника с владельцем; «Повторить чтение» не удаляет ключ и не обходится новым заказом. Сбой локального сохранения сохраняет блокировку/попытку для проверки; реальный отказ диска/браузерного хранилища не моделировался. Остальные W03–W12 открыты.
