# Приёмка опубликованного Web +37 — 01.10.2026

Пользователь сообщил о SSH-выкладке. Публичный version.json подтверждает 0.1.0+37; новая вкладка показывает фото ограниченной высоты и цену под названием. Проверка встроенным Chromium, без физического телефона/Android/iOS. Код приложения и сервер в этой сессии не менялись; версия остаётся +37.

## Результаты заказа

Тестовая запись «Автотест», дата 05.10.2026, разрешённый максимум 500 ₽. До начала календарь показывал «Нет заказа». Прежняя вкладка отсутствовала; после входа и подготовки даты серверный состав был пустым. Исторический суп 110 ₽ не считался актуальным серверным заказом.

| Операция | Состав и сумма | Фактическое подтверждение |
|---|---|---|
| Создание | Суп овощной 110 ₽ × 1, говядина с кус-кусом (мини) 190 ₽ × 1, салат из огурцов в соевой заправке 90 ₽ × 1; 390 ₽ | «Заказ принят сервером. 05.10.2026: 390 ₽»; календарь/история 390 ₽; при повторной подготовке все три позиции загружены |
| Изменение | Суп и второе без изменений, салат × 2; 480 ₽ | Серверная квитанция 480 ₽, календарь/история 480 ₽, повторная подготовка показала салат × 2 |
| Отмена | Очистить только 05.10 → «Отменить заказ на день» | «Изменения приняты. Заказ отменён.»; календарь «Нет заказа», итог следующей недели 0 ₽; повторное «Обновить историю» сохранило этот результат |

Максимум в черновике/принятом заказе — 480 ₽. Один цикл создания/изменения/отмены, без повторной отправки неопределённого результата. Неопределённой отправки в живом сценарии не возникло; механизм её проверки остаётся подтверждён автоматическими тестами. Идентификатор заказа UI не показал, он не выдумывается. Активного тестового заказа в финальном календаре нет.

До отправки проверены: суп 1→2→1→0→1, итоги 110→220→110→0→110 ₽; удаление супа кнопкой корзины до 280 ₽ и восстановление через «Добавить блюда»/каталог до 390 ₽. Серверные сохранения блокировали кнопки, затем показали квитанции.

## Дизайн и навигация

- Календарь на 320/360/390/430 px: две колонки, одинаковая высота дней в каждой раскладке, «Доступен», «Закрыт», слова «Нет заказа» без разрывов внутри слов. На 430 действие рядом и «Нет заказа» в две строки, на более узких действие под текстом.
- На 390 карточки компактнее, полный длинный заголовок читается, вес/цена/показатели рядом, плюс/минус работали. Полная карточка открылась, состав доступен.
- На 1200 сохранена одна колонка карточек и панели; на 1440 две. Фото целиком, цена под названием, «Полный состав» открыл диалог с ингредиентами.
- Обычный вход с from=/orders завершился в /orders. Первая быстрая попытка ввода дала invalid_credentials; повтор после явного фокуса и ввода пароля успешен. Это наблюдение автоматизации, не подтверждение дефекта входа.
- Успешная регистрация с новым кодом в этой сессии не повторялась: устройство уже зарегистрировано. Очистка старой ошибки, безопасный from, отсутствие/некорректный from, повторный вход, восстановление и Back форм покрыты регрессиями; полная новая живая регистрация остаётся ограничением приёмки.
- Масштаб текста 1,6 проверен widget-тестами с реальным Arial. В браузере в этой сессии текстовый масштаб не менялся; уменьшение viewport не выдаётся за такую проверку.

## Новые замечания

### P1 — Продолжение черновика после перезагрузки

1. Составить обед 05.10 на 390 ₽, открыть /cart, не отправлять.
2. Перезагрузить страницу. После восстановления сессии /cart показывает «Корзина пуста» и указание начать изменение дня.
3. В /menu позиции сохранили количества 1/1/1, но кнопки заблокированы.
4. /orders → «Заказать» 05.10 заменяет локальный состав серверным пустым; каталог показывает количество 0. Для отправки пришлось собирать обед заново.

Это не потеря серверного заказа: он ещё не отправлялся. UX-проблема подтверждена. Статический разбор согласуется с ней: CartEditState не сохраняется при перезапуске, editingCartProvider скрывает draft без active, begin всегда заменяет день серверным составом. Исправление должно повторно проверять доступность/владельца/revision, затем давать продолжить актуальный черновик; нельзя просто восстановить право отправки из хранилища.

### P2 — Браузерный Back из полной карточки

После отмены: /orders → обычный выбор 05.10 → нижнее «Меню» → фото супа → полная карточка. Вызов браузерного Back закрыл карточку и сразу сменил /menu на /orders/categories. Принятый сценарий требует сначала закрыть только слой и оставить /menu. Проверен один конкретный путь; кнопка приложения и физическая системная навигация в этой сессии отдельно не проверялись. Регрессия и исправление — отдельный следующий шаг.

## Остаток

Приёмка частичная: сквозной серверный цикл выполнен, календарь и компактность проверены в указанном объёме. Продолжение черновика после reload не принято, браузерный Back слоя требует исправления. Новая регистрация в браузере, живой увеличенный текст, физический телефон и установленный Android не проверены; iOS не запускалась. Следующая задача — FL-UX-06; публикация нового кода потребуется только после её реализации, текущая документация пересборки не требует.
