## Реализация

Корзина любого разрешённого дня готовит все даты загруженного меню с доставкой одним Orders/snapshot. Закрытые/неоднозначные ненажатые дни исключаются с объяснением; выбранный недоступный день отклоняется. Подготовленный состав, названия и revisions хранятся отдельно для каждой даты. Повторное нажатие, выбор даты, Back, страницы и resize сохраняют правки; Back во время незавершённой подготовки отменяет применение ответа.

CartWorkStore v1 — самостоятельный снимок обычного набора: ownerScope, выбранная дата, revisions, исходные составы/имена, текущие количества. Ключ изолирован по API, окружению, login и устройству, токен не сохраняется. Записи и очистка проходят одну очередь; отменённая подготовка очищает свой снимок до записи следующей. Ошибка записи видна пользователю и блокирует отправку до успешного сохранения. Legacy draft, repeat и pending сохраняют прежние форматы.

После перезапуска набор предлагается продолжить или сбросить с подтверждением. Продолжение обновляет меню и делает snapshot сохранённых дат; ownerScope, исходные версии/составы, доступность и наличие меню проверяются до применения пользовательских количеств. Конфликт/закрытие сохраняет локальный снимок. Повреждённое хранилище не даёт права изменения; доступны повтор чтения и подтверждённый сброс. Незавершённая отправка имеет приоритет над продолжением набора.

Вкладки отсортированы по календарю и прокручиваются горизонтально. Видимы непустые дни, отмены и выбранный пустой день. Выбор синхронизирует каталог. Показаны итог дня и статус изменения/отмены; общий итог «К сохранению» рассчитан только по отправляемым дням. В окне малой высоты итог становится компактнее, позиции продолжают прокручиваться.

Сравнение исходных/текущих количеств определяет отправляемые даты. Нетронутые дни и пустые новые заказы исключены; возврат к исходному снимает изменение. При отменах общий диалог перечисляет даты; контроллер проверяет точное подтверждённое множество. Один basket содержит только изменения, исходные revisions, один submissionId, includeSnapshot и expectedOwnerScope. Потеря ответа сохраняет pending; basketresult/not_found повторяет прежний ID и тело. Принятая квитанция остаётся принятой при ошибке обновления snapshot; успех завершает набор, сбой очистки сохраняет блокировку pending.

Максимум 31 дата: 31 сохраняется одним пакетом; 32 кандидата явно отклоняются до HTTP без сокращения/разбиения. Режим повтора сохраняет дополнительные проверки и прежнюю семантику. Обычный активный/сохранённый набор требует сброса перед переходом в повтор, чтобы не потерять правки.
