## Создание карточки

1. Открыть Home → Create app; использовать значения выше, проверить доступность package name.
2. Владелец проверяет юридические декларации Developer Program Policies и US export laws. Их принятие требует отдельного подтверждения в момент действия; подготовленная форма не доказывает соответствие открытым требованиям.
3. Проверить **Automatic protection**. В текущей форме Google предлагает installer check, который направляет пользователей защищённой версии из другого источника в Google Play. По разрешению владельца 05.10.2026 проверка установщика отключена: форма показала `You've turned off automatic protection`. Это отдельная настройка от Play App Signing.
4. После подтверждений создать карточку. Зафиксировать ссылку кабинета, app ID и статус Draft; убедиться, что package name совпадает с согласованным. Не редактировать карточку старого приложения.
5. Внести принятые тексты и контакты из канонического JSON; заполнить категорию, возрастной рейтинг, доступ модераторов и декларации по подтверждённым фактам. Политику/удаление не заменять временной заглушкой.

Правила создания и постоянства package name: [Play Console Help](https://support.google.com/googleplay/android-developer/answer/9859152?hl=en). Сведения удаления: [Google Play](https://support.google.com/googleplay/android-developer/answer/13327111?hl=en). Наблюдаемые поля кабинета могут отличаться от иллюстраций документации.

## Подпись и первоначальная загрузка

- До первого выпуска выбрать **собственный app signing key**, подготовленный в FL-07-05. Не выбирать новый ключ Google: схема обновлений между каналами требует общего сертификата устанавливаемых APK.
- Передать ключ только защищённым способом, предложенным Play Console; зарегистрировать отдельный upload certificate. Сверять публичные SHA-256 по инструкции восстановления, не печатать приватные ключи и пароли.
- Получить актуальную AAB, подписанную upload key. Проверить package name, версию, build, текущий target API и контрольную сумму. Старые артефакты +4 и исходники +70 не считать одной сборкой.
- Первую AAB загрузить вручную в **internal testing**, выполнить обязательные настройки кабинета и проверить установку тестировщиком. Если кабинет требует дополнительные проверки аккаунта, выполнить их по фактическому статусу; историческое сообщение владельца о регистрации до 13.11.2023 не заменяет проверку доступа к production.
- Из Play App Bundle Explorer получить доставляемый APK и сверить его app signing certificate с прямым APK/RuStore. Закрыть приёмку обновления с более высоким versionCode.

Основания: [Android app signing](https://developer.android.com/studio/publish/app-signing), [первоначальная загрузка Codemagic](https://docs.codemagic.io/yaml-publishing/google-play/). Публичный rollout остаётся отдельным результатом после закрытия блокеров.

## Доступ Google Play API и Codemagic

Владелец выбирает Google Cloud project, включает Google Play Android Developer API и создаёт выделенный service account `polevaya-kuhnya-release`. Старое связывание Cloud project с аккаунтом разработчика больше не требуется. [Google API: настройка](https://developers.google.com/android-publisher/getting_started).

В Play Console → Users and permissions добавить service account для **только нового приложения**. Разрешения: чтение информации приложения, управление тестовыми выпусками и production-выпусками. Финансовые права и администрирование аккаунта для загрузки не нужны. Предоставление доступа к выпуску требует отдельного подтверждения владельца в момент действия.

Создать JSON key и поместить его в Codemagic как secret `GOOGLE_PLAY_SERVICE_ACCOUNT_CREDENTIALS`, группа `google_play_release`. Не сохранять ключ в проект, build artifacts, документацию или чат. Доступ группы предоставлять только доверенному workflow; в будущем отделить режим подготовки от отправки. [Codemagic: доступы и переменные](https://docs.codemagic.io/yaml-publishing/google-play/).

Контракт будущего workflow: выбранный Git commit, версия из `pubspec.yaml`, `track: production`, `submit_as_draft: false`, отправка на review, без ограничения доли rollout. **Managed publishing отключён** для автоматической доступности после одобрения. Внутренний тест первой версии не должен автоматически продвигаться в production. Настройка workflow относится к следующей подзадаче и пока не добавлена в `codemagic.yaml`.

## Прямая установка APK

Уточнение владельца 05.10.2026: приложение должно устанавливаться напрямую из APK, полученного вне магазинов. Сохраняем отдельный универсальный APK, подписанный существующим app signing key; Google Play installer check не включаем. В собственном клиенте не добавляем обязательную проверку источника установки или лицензии Google Play.

Пользователь может получать официальный APK с сайта, из файла или другого канала передачи. Это не обещание установки произвольного изменённого APK: Android проверяет формат, совместимость устройства и подпись; пользователь разрешает установку из выбранного источника средствами ОС. Для обновления без удаления сохраняются package name, совместимый сертификат и более высокий versionCode. APK, подписанный upload key вместо app signing key, не использовать для прямого обновления.

В приёмку включить чистую установку официального APK без Google Play, запуск приложения, обновление поверх предыдущего прямого APK с сохранением данных и нужные направления обновления между магазинами и APK. Требования Android developer verification для распространения вне Google Play проверять отдельно по кабинету и регионам; отключение installer check их не отменяет.
